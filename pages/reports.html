Reports & Dashboards

Report types decide what data you can see, formats decide how it's shaped, and dashboards decide who sees whose numbers. Including the advanced features people rarely learn properly.

Report types — the foundation

A report type is a template that defines which objects and fields are available, and how related objects are joined. If a field isn't in the report type, no report can ever show it.

The two join behaviours
"Accounts with Opportunities" hides accounts that never bought. "Accounts with or without Opportunities" is how you find them.

Standard report types

Auto-created for every object and relationship. You can't edit them, and they always use "with" (inner join) semantics for the child.

Custom report types

You define: a primary object plus up to 3 related objects (4 total), each joined "with" or "with or without". You also choose which fields appear and can add fields via lookup.

🔎
Classic scenario question "Show me all Accounts that have no Opportunities." → Create a custom report type Accounts with or without Opportunities, then add the filter Opportunity ID = "" (equals blank). This "cross-object gap analysis" pattern comes up constantly.

Filters

  • Standard filters — Show Me (My/All), date field + range.
  • Field filters — up to 20, combined with filter logic like (1 AND 2) OR 3.
  • Filter logic supports AND, OR, NOT and brackets. It can't be used with certain filters (e.g. some standard ones).
  • Row limit (tabular only) — "Top 10 deals", which also unlocks charting for tabular reports.
  • Cross filters — the advanced one, below.

Advanced reporting features

🔗 Cross Filters

Filter a parent by the existence of children without adding child columns.

Accounts with Opportunities or Accounts without Cases, plus up to 5 sub-filters on the child (e.g. "without Cases where Status = Open").

Limit: 3 cross filters per report, 5 sub-filters each.

Use case: "Customers with an open Opportunity but no Support Case in 90 days" — an upsell list.

🪣 Bucket Columns

Categorise on the fly without creating a formula field.

Numeric: Amount → Small (<10k) / Medium / Large. Picklist: group 12 industries into 3 sectors. Text: group values into named buckets.

Limit: 5 buckets per report, 20 values per bucket.

Use case: deal-size analysis before the business agrees on a permanent field.

Σ Summary Formulas (PCF)

Calculate on grouped values. Formula type: Percent/Currency/Number, then choose the grouping level (Grand Summary, Group 1…).

WON:SUM / CLOSED:SUM   → win rate %
AMOUNT:SUM / RowCount  → average deal

Limit: 5 per report. Cannot be used in filters or grouped by.

📏 Row-Level Formulas

A formula evaluated per row, created inside the report — no schema change needed.

TODAY() - DATEVALUE(CreatedDate)   → age in days

Limit: 1 per report, 3,900 characters. Can be filtered on and grouped in most cases.

📈 Historical Trend Reporting

Compare a field's value today vs 5 snapshot dates back. Enabled per object (up to 3 objects, 8 fields each, 3 months of history).

Use case: "Which deals slipped their Close Date since last month?"

📸 Reporting Snapshots

Schedule a report to write its rows into a custom object on a schedule — building your own history.

Source report must be tabular or summary; you map report columns → custom object fields.

Use case: capture open pipeline every Friday to trend it over years.

🆚
Row-level formula vs Summary formula Row-level = one value per record row (like a formula field). Summary formula = one value per group/total. If you need "days open" per case → row-level. If you need "% won by region" → summary.

Other things to know

  • Conditional formatting — colour rules on summary values (up to 5 rules).
  • Subscriptions — schedule a report to email you, or set conditions ("only email me if Amount < target"). Up to 7 per user.
  • Report folders — access is Viewer / Editor / Manager, shared with users, roles or public groups. This is how you secure reports.
  • Field-level security still applies — a report can never expose a field the user can't see.
  • Export — Formatted (keeps grouping, xlsx) vs Details Only (raw csv/xlsx).
  • Report limits: 2,000 rows displayed in the browser, 20,000 in the printable view, 100,000 on export. Dashboards show the top 20 (chart) / 2,000 (table) values.

Dashboards

A dashboard is a visual layer over reports. Each component points at exactly one report.

Component types

  • Bar / Column (stacked, grouped)
  • Line
  • Donut / Pie / Funnel
  • Gauge (with breakpoints)
  • Metric (single number)
  • Table (with conditional formatting)
  • Scatter
  • Lightning table (multi-column, drill-down)

Key settings

  • Up to 20 components per dashboard
  • Up to 3 filters, 50 values each
  • Refresh: manual, or scheduled (daily/weekly/monthly)
  • Subscribe to get it emailed
  • Themes and 12-column grid layout

Placement

  • Dashboard tab
  • Embedded on a Lightning Home page
  • Embedded on a record page (filtered by that record)
  • Emailed as a subscription

Running User — the concept that trips everyone up

Whose data does the viewer see?
⚠️
Security implication A dashboard set to "Run as a specified user" can leak data: if the running user is a VP, every viewer sees VP-level numbers regardless of their own sharing. This is intentional but must be a conscious decision.

Reporting from code & SOQL

// Run a report synchronously and read its summary values
Report rpt = [SELECT Id, DeveloperName FROM Report WHERE DeveloperName = 'Pipeline_By_Stage' LIMIT 1];
Reports.ReportResults results = Reports.ReportManager.runReport(rpt.Id, true);
Reports.ReportFactWithDetails fact =
    (Reports.ReportFactWithDetails) results.getFactMap().get('T!T');
for (Reports.SummaryValue sv : fact.getAggregates()) {
    System.debug(sv.getLabel());
}

// Aggregate SOQL — often simpler than a report for code
List<AggregateResult> ars = [
    SELECT StageName stage, SUM(Amount) total, COUNT(Id) cnt
    FROM Opportunity
    WHERE CloseDate = THIS_QUARTER
    GROUP BY StageName
    HAVING SUM(Amount) > 100000
    ORDER BY SUM(Amount) DESC
];
for (AggregateResult ar : ars) {
    System.debug(ar.get('stage') + ': ' + ar.get('total'));
}

Interview questions

1 A field exists on the object but you can't add it to a report. Why?Easy

Three possibilities, in order of likelihood: ① the field isn't included in the custom report type's selected field list — edit the report type and add it; ② field-level security hides it from your profile, and reports never bypass FLS; ③ the field lives on a related object that the report type doesn't include, or is beyond the 4-object limit of a custom report type.

2 Explain "with" vs "with or without" in a custom report type.Medium

"A with B" is an inner join — only A records that have at least one B. "Accounts with Opportunities" silently hides every account that never bought.

"A with or without B" is an outer join — all A records, with B fields blank where there's no child. This is how you find gaps: add the filter Opportunity ID equals "" to list accounts with no opportunities.

3 Row-level formula vs summary formula (PCF) — when do you use each?Medium

Row-level formula produces one value per record row, like a formula field but scoped to the report — e.g. TODAY() - DATEVALUE(CreatedDate) for case age. Limit: 1 per report, and it can usually be filtered and grouped on.

Summary formula produces one value per group or grand total — e.g. WON:SUM / CLOSED:SUM for win rate. Limit: 5 per report; it cannot be used in filters or as a grouping.

4 What is a cross filter and what problem does it solve?Medium

It filters the primary object by the existence or absence of child records without adding child columns — "Accounts with Opportunities", "Accounts without open Cases". You can add up to 5 sub-filters on the child object, and 3 cross filters per report.

Typical use: an upsell list of "customers with an open Opportunity but no support Case in 90 days" — impossible with ordinary field filters.

5 200 reps must each see only their own numbers on one dashboard. How, and what's the catch?Medium

Set the dashboard to run as the logged-in user — a dynamic dashboard. Each viewer sees data through their own sharing.

The catches: dynamic dashboards cannot be scheduled or subscribed to, and there's a cap per edition (5 in Enterprise, 10 in Unlimited/Performance). If the business needs a scheduled email, you need a static running user instead — which means everyone sees that user's numbers.

6 The business wants to trend open pipeline over three years. What do you build?Hard

Reports show current state, so you need to capture history. Use a Reporting Snapshot: a source report (tabular or summary) whose rows are written on a schedule into a custom object, with column-to-field mapping. Then report on that custom object over time.

Historical Trend Reporting is the lighter alternative but only keeps ~3 months across 3 objects and 8 fields — good for "which deals slipped since last month", not multi-year trending.

7 How do you secure reports and dashboards?Easy

Through folders. A report/dashboard folder is shared with users, roles or public groups at Viewer, Editor or Manager level — that controls who can open or change it. Data visibility is separate: the report always respects the running user's sharing and FLS, except that a dashboard with a fixed running user shows that user's data to everyone who can open the folder. That combination is the usual source of accidental data exposure.

8 Which report format supports a chart, and what's the tabular exception?Easy

Summary, Matrix and Joined support charts because they have groupings to plot. Tabular can't — unless you set a row limit ("Top 10 deals"), which unlocks charting for use in a dashboard. Matrix is the only format with both row and column groupings (2 each); Summary allows up to 3 row groupings; Joined allows up to 5 blocks from different report types.

Quick check

1. You need "Accounts with no Opportunities". What do you build?
Cross filters are built exactly for existence/non-existence questions. The "with or without" custom report type plus an ID = "" filter is the classic alternative.
2. 200 reps each need to see only their own pipeline on the same dashboard. Setting?
Dynamic dashboards run in the viewer's context. Trade-off: they can't be scheduled or subscribed to.
3. Which format supports both row and column groupings?
Matrix = pivot table: 2 row groupings and 2 column groupings.
