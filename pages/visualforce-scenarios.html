Visualforce & Aura — 100 Scenarios

View state, postbacks versus remoting, PDF generation, Aura events, LockerService and LWS, and the migration decisions on legacy UI you still have to maintain.

📚
How to use this Answer out loud in ninety seconds, then open the answer. Concepts on Visualforce & Aura and its Advanced section.

View state (1–16)

1 "Maximum view state size limit exceeded" on a list page.Easy

You are holding the whole result set in controller member variables, which are serialised into the 170KB view state on every postback.

Mark re-derivable members transient, select fewer fields, and page with StandardSetController so only the current page is retained.

2 How do you find what is actually consuming view state?Easy

Enable Development Mode and open the View State tab — it breaks the size down by component tree, state and individual controller members.

It names the culprit in seconds. Guessing which variables to mark transient is slower and usually wrong.

3 What exactly does transient do?Easy

Excludes the member from view state serialisation, so it is null at the start of each postback and must be rebuilt — typically in a getter with a null check.

Use it for anything re-derivable: query results, maps built for rendering, describe results, caches.

4 A page with 60 selected fields over 500 rows is slow.Medium

30,000 field values serialised into view state and back on every interaction. The query is not the problem; the round trip is.

Select only the fields the page renders, and reduce the rows held. This single change fixes most legacy Visualforce performance.

5 You need to keep a user's selections across postbacks.Medium

That state genuinely must persist, so keep it small and non-transient — a Set<Id> of selected Ids rather than a list of full wrapper objects.

Store identifiers, rebuild the objects. That is the general pattern for everything in view state.

6 A wrapper list makes view state explode.Medium

Each wrapper holds a full sObject plus your extra fields, all serialised. Mark the list transient and rebuild it from a retained set of Ids plus a fresh query.

Or move the interaction to JavaScript Remoting and avoid view state entirely.

7 Does view state apply to JavaScript Remoting?Easy

No — @RemoteAction calls are stateless JSON requests with no view state at all.

Which is why remoting is the right choice for anything interactive on a page you must keep on Visualforce.

8 A page works for you and fails for a user with more data.Medium

View state scales with the data the page holds, so a user whose account has 2,000 contacts breaches a limit you never hit.

Bound the query with a LIMIT and page it. Unbounded Visualforce lists are a failure with a date on them.

9 You cannot reduce view state any further.Medium

Then the page design is wrong for a postback model. Rewrite the interactive parts with JavaScript Remoting and client-side rendering, or rebuild as an LWC.

Fighting a 170KB ceiling with transient keywords has a limit.

10 Does a rerender still post the whole view state?Medium

Yes — a partial page refresh is still a postback carrying the full view state in both directions. It only limits what is redrawn.

So rerender improves perceived rendering, not the payload. That surprises people.

11 Can you avoid view state on a read-only page?Easy

Largely, yes: a page with no form and no postbacks holds minimal state, and readonly="true" on the page also raises the query row ceiling considerably.

Useful for large reports and printable views.

12 What does readonly="true" change?Medium

It raises the number of rows the page can query substantially, at the cost of disallowing DML from the page.

The right setting for large read-only reports; useless for anything with a form.

13 Inner classes in your controller are inflating view state.Medium

Every non-transient field of every retained instance is serialised, including inner-class members.

Slim the inner class to what must persist, or mark the containing collection transient and rebuild it.

14 A map built purely for rendering is costly.Easy

Classic case for transient: rebuild it in a getter on each request from the retained identifiers.

Rendering convenience structures should essentially never be persisted.

15 How much view state is acceptable?Medium

As little as the page needs to function — and well under the ceiling, because data growth will take the rest.

Treat anything above roughly half the limit as a warning that the page will break for somebody's data.

16 Is view state a security concern?Hard

It is encrypted and tamper-protected by the platform, so it is not directly readable — but anything you put in it is being shipped to the browser and back.

Do not hold secrets or data the user should not have in controller state, and do not rely on it as an authorisation mechanism.

Controllers & data access (17–34)

17 Standard controller or custom?Easy

Standard controller when you want the platform's save behaviour, FLS handling and layout awareness for free — a simple record page.

A custom controller or extension when you need your own query, logic or navigation. An extension keeps the standard behaviour and adds to it.

18 Does a standard controller enforce FLS?Medium

Yes — apex:inputField and apex:outputField respect field-level security and render according to field metadata.

Hand-rolled apex:inputText bound to a field does not, which is a common way legacy pages leak or accept data they should not.

19 A custom controller does not enforce sharing.Medium

Controllers default to system mode unless declared with sharing — and even then FLS is not enforced.

Declare with sharing and use WITH USER_MODE on queries, or Security.stripInaccessible.

20 When would you choose JavaScript Remoting?Medium

For anything interactive: no view state, stateless JSON calls, and client-side rendering — the closest Visualforce gets to a modern architecture.

@RemoteAction methods are static, so they cannot see controller state, which is both the constraint and the point.

21 A @RemoteAction method cannot access controller variables.Easy

Correct — it is static. Pass everything it needs as parameters and return a serialisable result.

That statelessness is why there is no view state cost, so work with it rather than around it.

22 Remote Objects — when are they useful?Medium

Declarative CRUD from JavaScript with no Apex at all — genuinely useful for simple record access on a page you are not rewriting.

Limited for anything involving logic or complex queries, where remoting with Apex is the better choice.

23 You need a long-running callout from a Visualforce page.Hard

Continuations — the request is parked server-side without holding a thread, and a callback resumes it. Up to three can be chained.

It is the only way to do this without consuming a concurrent long-running request slot that interactive users share.

24 An action method runs twice on one click.Medium

Usually a double submit, or a rerender region that re-invokes a getter with a side effect.

Disable the button on click, and keep getters side-effect free — a getter that performs DML or increments a counter will behave unpredictably.

25 Getters are being called many times per request.Medium

Expected — the framework may evaluate a getter several times per lifecycle. Cache the result in a transient member with a null check.

A getter that queries on every call is one of the standard causes of a Visualforce page hitting SOQL limits.

26 A page hits "Too many SOQL queries".Easy

Queries in getters that are evaluated repeatedly, or a query inside an apex:repeat.

Query once into a transient member and have the getter return it. Never query inside a repeated component.

27 You need to pass data between two Visualforce pages.Medium

URL parameters for identifiers, or a shared controller when both pages use the same one.

Do not try to carry objects across pages — pass the Id and re-query. URL parameters are also visible to the user, so never put anything authoritative in them.

28 A URL parameter is being used to decide access.Hard

That is a vulnerability: the user controls it. An Id in the URL must still be access-checked server side.

Query with sharing enforced, and confirm the record is one this user may see rather than trusting that they were given the link.

29 How do you handle validation errors on a form?Easy

ApexPages.addMessage with a severity, rendered by apex:pageMessages — and field-level errors via SObject.addError when saving through a standard controller.

A page with no apex:pageMessages swallows errors silently, which is a frequent legacy bug.

30 A save silently does nothing.Medium

Almost always a validation or required-field error with nowhere to render — add apex:pageMessages.

Second candidate: a rerender that excludes the messages region, so the error is produced and never displayed.

31 You need a wizard across several screens.Medium

One controller shared across pages, with the state held deliberately and minimally — or better, a screen flow, which handles navigation and state for you.

Hand-built Visualforce wizards are where view state problems concentrate.

32 An apex:repeat over 5,000 rows times out.Medium

Rendering cost plus view state. Page it with StandardSetController, or render client-side from a remoting call.

Visualforce was never designed to render thousands of rows in one request.

33 How do you implement pagination properly?Medium

StandardSetController with a page size gives you next/previous and record count with minimal state.

For very deep paging, a keyset approach (WHERE Id > :lastId ORDER BY Id) performs far better than OFFSET.

34 A controller is 1,200 lines.Medium

Extract the business logic into a service class the controller calls — testable without the page, and reusable if you later rebuild the UI as an LWC.

That extraction is also the first step of any migration, so it is never wasted work.

PDF & email (35–50)

35 You need to generate a branded PDF invoice.Easy

renderAs="pdf" on a Visualforce page — still the most practical built-in option, and a legitimate reason Visualforce survives.

Expect an older rendering engine: table-based layout, inline or embedded CSS, and @page for size and margins.

36 Flexbox and grid do not work in your PDF.Easy

The PDF renderer does not support them. Use tables for layout — genuinely, this is the one place table layout is correct.

Also avoid external stylesheets, which load unreliably; inline or embed the CSS.

37 Non-Latin characters render as boxes.Medium

The default font lacks those glyphs. Embed a font via a static resource and @font-face.

This is the standard fix for Arabic, CJK, Cyrillic and Greek content, and it needs testing with real data.

38 PDF generation fails for large documents.Medium

Heap and size ceilings. A 500-page document will not render in one request.

Split into smaller documents, or generate asynchronously in batches and combine outside Salesforce. Decide the page-count limit you support and enforce it.

39 Images are missing from the PDF.Medium

The renderer must be able to fetch them without a session — so static resources or documents, not session-protected URLs.

Base64-embedding small images is another reliable option.

40 Page breaks fall in the wrong place.Medium

Use CSS page-break-before/page-break-inside on the containing elements, and keep table rows from splitting where it matters.

Test with realistic content lengths — page breaks are fine until a description field is three paragraphs long.

41 You need a header and footer on every page.Medium

@page margin boxes with CSS, which the renderer supports for repeating headers and footers including page numbers.

It is fiddly and worth building once as a reusable component for all your documents.

42 A PDF must be attached to a record automatically.Medium

PageReference.getContentAsPDF() in Apex, then save the blob as a ContentVersion or Attachment.

Beware the callout-and-DML ordering rules and the heap cost of the blob — for bulk generation, do it in batches asynchronously.

43 getContentAsPDF() throws in a trigger.Medium

It behaves like a callout in several respects and is not permitted in all contexts, particularly after DML.

Move it to an asynchronous context — a Queueable or Batch — which is also where you want the heap headroom.

44 A Visualforce email template is the right choice when?Medium

When the email needs related lists, loops, conditional sections or complex data — things Classic and Lightning email templates handle poorly.

It remains genuinely useful, and it is a second legitimate reason Visualforce still exists.

45 The email template renders differently in Outlook.Medium

Email clients are far more restrictive than browsers: table layout, inline CSS, no modern selectors.

Test in the clients your recipients actually use, and keep the markup deliberately primitive.

46 A PDF must be generated for 10,000 records nightly.Hard

Batch Apex with a small scope, generating and saving each document — and expect it to be slow, because each render is a page request.

At that volume, consider whether a document-generation service outside Salesforce is a better fit for cost and speed.

47 You need a Word document rather than a PDF.Medium

Visualforce can emit other content types via contentType, which gets you a basic RTF or HTML-as-doc output.

For genuine .docx fidelity, use a third-party document generation tool — hand-rolling Office formats in Apex is not a good use of anyone's time.

48 The PDF must be identical to a designer's mockup.Medium

Set the expectation early: the renderer is limited, so pixel-identical output is often not achievable.

Agree the layout against a rendered proof rather than a web mockup, or use a dedicated document tool if fidelity is genuinely contractual.

49 How do you test PDF generation?Medium

In Apex, assert that getContentAsPDF() returns a non-empty blob and that the controller produced the expected data — you cannot assert on visual layout.

Visual verification is a manual step with realistic data, including the long-content and missing-data cases.

50 Should new document generation use Visualforce?Medium

For PDFs on-platform, yes — it is still the pragmatic built-in option and there is no LWC equivalent.

That is a narrow exception. Everything interactive should be LWC.

Aura (51–68)

51 An application event wakes dozens of components.Hard

Application events broadcast to every component that handles them, anywhere on the page — the classic Aura performance and debugging problem.

Prefer component events (which bubble through containment), and in LWC the equivalent discipline is to avoid composed: true unless necessary.

52 Component event versus application event.Medium

Component events travel the containment hierarchy with capture and bubble phases — scoped and traceable. Application events go everywhere.

Default to component events. Application events are for genuinely page-wide concerns, and even then they are hard to reason about.

53 A server action callback fires twice.Hard

Storable actions: the framework may return a cached response immediately and then a fresh one, invoking your callback twice.

Make callbacks idempotent and check the action state. Non-idempotent handlers behind storable actions produce genuinely confusing bugs.

54 When should an action be storable?Medium

Read-only, cacheable data where a slightly stale first paint is acceptable — it makes the page feel much faster.

Never for anything that writes, and never where the double callback would cause a side effect.

55 An Aura component is slow to load.Medium

Aura has a heavier client-side bootstrap than LWC, and the usual culprits are too many components and several server calls on init.

Consolidate the server calls, lazy-load what is not visible, and consider whether the component should be rebuilt as an LWC.

56 Can an LWC be nested inside an Aura component?Easy

Yes — and not the reverse. That asymmetry dictates migration order: rebuild the innermost components first and let the Aura shell remain temporarily.

Attempting to migrate the outer container first leaves you unable to host the children you have not converted yet.

57 An Aura component must talk to an LWC.Medium

Pass data down via attributes, and let the LWC fire a CustomEvent the Aura parent handles — or use Lightning Message Service for anything less structural.

LMS also reaches Visualforce, which makes it the bridge of choice during a mixed-technology migration.

58 aura:method versus an event.Medium

aura:method is a direct parent-to-child call — appropriate for imperative actions like reset or validate.

Events are for child-to-parent notification. Using an event where a method would do adds indirection; using a method where a property would do adds coupling.

59 An Aura attribute change does not re-render.Medium

Aura's change detection differs from LWC's: you may need an explicit change handler, and deep mutations are not always observed.

Set the attribute to a new value rather than mutating its contents — the same discipline that LWC requires.

60 LockerService broke a third-party library.Medium

Locker restricted DOM and global access. Lightning Web Security has since replaced it with a different sandboxing model, and many libraries that failed under Locker now work.

Re-test rather than relying on what was true years ago.

61 What changed moving from Locker to LWS?Medium

A different isolation approach with fewer JavaScript restrictions, so more third-party code works — but some behaviours differ, particularly around DOM access and globals.

Treat the migration as a regression-test exercise for anything using external libraries.

62 An Aura component works in the app and fails in a community.Medium

Different runtime and theming, guest-user context, and some APIs unavailable.

Test as the actual community persona. If the site is LWR, Aura components are not supported there at all — which is frequently the real answer.

63 How do you debug an Aura component?Medium

Browser devtools for the network calls and console, plus the Lightning Usage App for EPT at page level.

Aura's error messages are often unhelpful, so logging around the action callbacks is usually faster than reading the stack.

64 An Aura component needs a record page context.Easy

Implement the appropriate interface so recordId is injected, and declare where the component can be used in its design file.

The same pattern as LWC targets — and getting it wrong means the component does not appear in App Builder.

65 Should you write new Aura components?Easy

No. LWC for everything new — better performance, a standards-based model, and the direction of the platform.

Existing Aura is a maintenance commitment, not a template for new work.

66 An Aura component is business-critical and nobody understands it.Hard

Document the behaviour first, then extract the server-side logic into a service class so it is testable independently of the UI.

That extraction both de-risks the current component and is the first step of the eventual rewrite.

67 Aura's $A.enqueueAction batching surprises you.Hard

Actions are queued and sent in batches, so ordering and timing are not what a sequential reading of the code suggests.

Do not rely on action order; chain dependent calls through callbacks, or restructure so each call is independent.

68 How do you decide what to migrate first?Medium

By usage and risk: the Lightning Usage App tells you what is actually used, and plenty of legacy components are used by nobody.

Deleting the unused ones is the cheapest migration available. Then migrate the high-usage, high-risk ones leaves first.

Migration (69–86)

69 Where do you start a Visualforce-to-LWC migration?Medium

Inventory and measure: pages by usage, by business criticality, by complexity. Then delete what nobody uses.

After that, migrate leaves before containers, and replace the data layer early — swapping @RemoteAction for @AuraEnabled cacheable methods or LDS often removes most of the Apex.

70 Should you transliterate the page element by element?Medium

No — a postback-oriented design translated literally produces poor LWC. Re-express the requirement.

Frequently the LWC version needs a fraction of the code because LDS and base components replace what the controller was doing.

71 An integration depends on your Visualforce page URL.Medium

That URL is a contract. Keep the page as a thin redirect or wrapper during migration, or coordinate the change with the consumer.

Check the Setup references and your integration register before deleting any page with a predictable URL.

72 How do you keep a rollback position during migration?Medium

Leave the old page available behind a permission or a feature flag until the replacement has run in production for a cycle.

The rollback story matters more than the elegance of the cutover.

73 A Visualforce page is embedded in a Lightning record page.Medium

It works, inside an iframe, with the attendant styling and communication awkwardness — and Lightning Message Service is how you talk to it.

It is a reasonable interim state, and a poor permanent one.

74 Styling does not match after embedding in Lightning.Medium

The page carries its own styling and does not inherit the Lightning theme. Apply SLDS inside the page, and set applyHtmlTag/applyBodyTag deliberately.

It will never look native. If appearance matters, that page is a migration candidate.

75 sforce.one navigation does not work.Medium

It is only available when the page is running inside Lightning — so a page that works standalone breaks embedded, or vice versa.

Detect the context and branch, or navigate from an LWC wrapper instead.

76 Visualforce in Experience Cloud.Medium

Supported in Aura-template sites with caveats; not a good fit for LWR, which is where new sites should be.

Guest-user context also applies, so the page's controller must be reviewed for the same exposure risks as any public surface.

77 How do you migrate a controller's logic safely?Medium

Extract it into a service class with tests first, while the page still works. Then the LWC calls the same service.

That way the behaviour is pinned by tests before the UI changes, and a regression is attributable.

78 Your LWC replacement is slower than the Visualforce page.Medium

Usually several Apex calls on load where the Visualforce page did one query, or rendering too much at once.

Consolidate into one call returning a composite payload, lazy-load the rest, and measure with component instrumentation.

79 Users prefer the old page.Medium

Usually a workflow regression rather than nostalgia: a keyboard shortcut, a dense layout, or fewer clicks in the old version.

Watch someone use both. Migrating the technology while degrading the task is a net loss.

80 How do you find every Visualforce page still in use?Medium

The Lightning Usage App and page-view data for traffic, plus Setup dependency references, buttons, links, email templates and integrations.

A page with no traffic and no references is safe to delete — and that is a meaningful share of most legacy estates.

81 Deleting a page breaks a custom button.Easy

Check the "Where is this used?" dependencies before deleting anything — buttons, links, layouts, flows and email templates all reference pages.

Deployment will usually block a genuinely referenced delete, but not every reference type is caught.

82 A migration is half-finished and stalled.Medium

The common state. Make sure each migrated piece is independently complete and shipped, so partial progress is still value.

A migration structured as one big cutover stalls permanently; one structured as many small replacements survives changing priorities.

83 How do you justify migration effort to the business?Medium

In their terms: page performance, mobile support, maintainability cost, and the risk of a shrinking pool of people who can work on it.

"It is old technology" loses the argument. "This page cannot be used on mobile and takes six seconds to load" wins it.

84 Should you migrate a page that works fine?Medium

Not for its own sake. A stable internal admin utility nobody looks at is not a priority.

Migrate when there is a reason: it needs changes, it must work on mobile, it is slow, or it blocks something. Churn without benefit is still churn.

85 What is the honest remaining role for Visualforce?Medium

PDF generation, complex data-driven email templates, stable internal utilities, and pages embedded in long-lived integrations expecting a URL.

Everything interactive, mobile or reusable should be LWC.

86 An interviewer asks whether Visualforce is dead.Medium

Say no, and be specific: LWC for anything new, but Visualforce still earns its place for PDF and complex email templates, and plenty of orgs have thousands of working pages.

Then describe the migration approach — by usage and risk, leaves first, rebuild rather than transliterate. That demonstrates judgement rather than fashion.

Judgement (87–100)

87 You inherit 400 Visualforce pages.Hard

Inventory by usage and references, delete the dead (usually a large fraction), then rank the rest by risk and need.

Do not plan a 400-page migration. Plan the next ten, shipped independently.

88 A page fails only for one user.Medium

View state, driven by their data volume, or FLS on a field the page assumes is visible.

Log in as them. Legacy pages frequently assume the developer's own permissions.

89 A legacy page has no tests.Medium

Write tests around the controller's current behaviour before changing anything — including the parts you believe are wrong.

Controller tests are straightforward: set up the page reference, instantiate, call the action methods, assert the resulting state.

90 How do you test a Visualforce controller?Easy

Set Test.setCurrentPage with any parameters, construct the controller (with a StandardController if it is an extension), call the action methods, and assert on the state and the resulting PageReference.

Also assert the error path, which is where legacy controllers are weakest.

91 An old page runs on a very old API version.Medium

It keeps that version's semantics, which is a stability guarantee and accumulating debt.

Bump it deliberately with regression testing as a maintenance task, not silently while making an unrelated change.

92 Security review flags a legacy page.Hard

Likely causes: controller in system mode without FLS enforcement, apex:inputText bound to fields bypassing FLS, URL parameters trusted for access, or output not escaped.

Prioritise anything reachable by guest or external users — that is where the real exposure is.

93 Is output escaped by default in Visualforce?Hard

Largely yes, and escape="false" is how legacy pages introduce XSS.

Audit every escape="false" and every place HTML is assembled in the controller. User-supplied content must never be rendered unescaped.

94 A page builds HTML strings in Apex.Hard

An injection risk and unmaintainable. Render with components and let the framework escape, or escape explicitly with the platform's utilities.

String-built HTML is one of the clearest signals a page needs rewriting.

95 How do you prioritise legacy UI work against new features?Medium

Reserve a fixed slice of each sprint rather than competing on priority — legacy work always loses a direct comparison.

Target the pages that are blocking something or failing users, so the work has a visible beneficiary.

96 A stakeholder wants the old page kept "just in case".Medium

Agree a sunset date and measure usage in the meantime. Usually the data settles it within a month.

Indefinitely maintaining two versions of the same screen is the worst of both options.

97 What is the most common legacy Visualforce problem?Hard

View state driven by unbounded data — a page that worked for five years and now fails for the customers with the most records.

Closely followed by queries in getters, and controllers running in system mode with no FLS enforcement.

98 How do you make a legacy page safe to leave alone?Medium

Bound its queries, mark re-derivable state transient, enforce FLS and sharing, add controller tests, and document what it does.

Then it can wait. An unbounded, untested page in system mode cannot be safely ignored.

99 When is rewriting cheaper than fixing?Medium

When the page's design fights the platform — a postback-heavy interactive screen hitting view state limits — so each fix buys little.

When the problems are bounded (one slow query, one missing check), fixing is far cheaper.

100 One habit for working with legacy UI?Hard

Extract the logic into a tested service class before you touch the UI.

It makes the current page safer, makes the behaviour explicit, and means the eventual rewrite is a presentation change rather than a re-derivation of business rules nobody documented.
