Visualforce & Aura

The two generations of UI before LWC. Still very much alive in real orgs — and still asked about in interviews. Plus a clear comparison of all three.

Visualforce

A server-side, tag-based markup language (2008). The page is assembled on the server, sent as HTML, and every interaction posts back to the server.

Rich, data-driven emails with full markup control.

public with sharing class AccountDashboardExtension {

    private final Account account;
    private ApexPages.StandardController stdCtrl;

    public List<Contact> contacts { get; private set; }
    public Integer contactCount   { get { return contacts == null ? 0 : contacts.size(); } }
    public Id selectedContactId   { get; set; }

    // Extension constructor MUST take a StandardController
    public AccountDashboardExtension(ApexPages.StandardController controller) {
        this.stdCtrl = controller;
        // addFields must be called before getRecord() in non-test contexts
        if (!Test.isRunningTest()) {
            controller.addFields(new List<String>{ 'Name', 'Industry', 'AnnualRevenue' });
        }
        this.account = (Account) controller.getRecord();
        loadContacts();
    }

    private void loadContacts() {
        contacts = [SELECT Id, Name, Email FROM Contact
                    WHERE AccountId = :account.Id WITH USER_MODE ORDER BY Name];
    }

    public PageReference removeContact() {
        try {
            delete [SELECT Id FROM Contact WHERE Id = :selectedContactId];
            loadContacts();
            ApexPages.addMessage(new ApexPages.Message(ApexPages.Severity.CONFIRM, 'Contact removed'));
        } catch (DmlException e) {
            ApexPages.addMessage(new ApexPages.Message(ApexPages.Severity.ERROR, e.getDmlMessage(0)));
        }
        return null;                       // null = stay on the same page
    }

    public PageReference saveAndRedirect() {
        update account;
        PageReference pr = new PageReference('/' + account.Id);
        pr.setRedirect(true);
        return pr;
    }
}

View state — the classic Visualforce problem

Every <apex:form> carries an encrypted hidden field containing all the controller state needed to rebuild the page on postback. It is capped at 170 KB.

What bloats it

  • Large collections held in non-transient member variables
  • Querying more fields/rows than the page displays
  • Wrapper objects holding whole sObjects
  • Multiple forms on one page
  • Component tree size itself

How to fix it

  • Mark variables transient — excluded from view state
  • Use StandardSetController for pagination
  • Query only the fields you render, with a LIMIT
  • Use <apex:actionRegion> to submit only part of the form
  • Move logic client-side with JS Remoting / @RemoteAction
  • Check the View State tab in the Developer Console
public class BigListController {
    // NOT in view state — recalculated on every request
    public transient List<Account> accounts { get; set; }

    // In view state — keep it small
    public String searchTerm { get; set; }

    public BigListController() { loadAccounts(); }
    private void loadAccounts() {
        accounts = [SELECT Id, Name FROM Account LIMIT 200];
    }
}

<apex:page controller="RemoteController">
<script>
    function search(term) {
        Visualforce.remoting.Manager.invokeAction(
            '{!$RemoteAction.RemoteController.findAccounts}',
            term,
            function(result, event) {
                if (event.status) { render(result); }
                else { console.error(event.message); }
            },

        );
    }

global with sharing class RemoteController {
    @RemoteAction
    global static List<Account> findAccounts(String term) {
        String key = '%' + String.escapeSingleQuotes(term) + '%';
        return [SELECT Id, Name FROM Account WHERE Name LIKE :key WITH USER_MODE LIMIT 20];
    }
}

🖨️
PDF gotchas The PDF renderer is old: no JavaScript, limited CSS, no Lightning components, and non-Latin characters need font-family: 'Arial Unicode MS'. Max render time 10 minutes / 60 MB heap. Modern alternative: a third-party PDF service called from Apex.

Visualforce security

  • Output is HTML-escaped by default. escape="false" or <apex:outputText escape="false"> opens you to XSS — only use with sanitised content.
  • {!$CurrentPage.parameters.name} is user input — never trust it in SOQL or output without escaping.
  • Standard controllers enforce CRUD/FLS/sharing automatically; custom controllers do not. Declare with sharing and check isAccessible().
  • Use JSENCODE(), HTMLENCODE(), URLENCODE(), JSINHTMLENCODE() in markup.

<aura:component controller="AccountController"
                implements="flexipage:availableForAllPageTypes,force:hasRecordId"
                access="global">

    <aura:attribute name="accounts" type="Account[]" />
    <aura:attribute name="recordId" type="Id" />
    <aura:attribute name="isLoading" type="Boolean" default="false" />

    <aura:handler name="init" value="{!this}" action="{!c.doInit}" />
    <aura:registerEvent name="accountSelected" type="c:AccountSelectedEvent" />

    <lightning:card title="Accounts">
        <aura:if isTrue="{!v.isLoading}">
            <lightning:spinner />
            <aura:set attribute="else">
                <aura:iteration items="{!v.accounts}" var="acc">
                    <p onclick="{!c.handleSelect}" data-id="{!acc.Id}">{!acc.Name}</p>
                </aura:iteration>
            </aura:set>
        </aura:if>
    </lightning:card>
</aura:component>
({
    doInit : function(component, event, helper) {
        helper.loadAccounts(component);          // controllers stay thin
    },
    handleSelect : function(component, event, helper) {
        var id = event.currentTarget.dataset.id;
        var evt = component.getEvent("accountSelected");
        evt.setParams({ accountId : id });
        evt.fire();
    }
})
({
    loadAccounts : function(component) {
        component.set("v.isLoading", true);
        var action = component.get("c.getAccounts");   // server-side Apex method
        action.setParams({ limitSize : 10 });
        action.setCallback(this, function(response) {
            var state = response.getState();
            if (state === "SUCCESS") {
                component.set("v.accounts", response.getReturnValue());
            } else if (state === "ERROR") {
                console.error(response.getError()[0].message);
            }
            component.set("v.isLoading", false);
        });
        $A.enqueueAction(action);                      // queued, then batched
    }
})

Interoperability rules An Aura component can contain an LWC, but an LWC cannot contain an Aura component. That's why migration goes leaf-first: rewrite the innermost components as LWC, keep the Aura shell, then replace the shell last. Both can talk through LMS.

Interview questions

1 Standard controller, custom controller or extension — which and when?Easy

Standard controller for simple CRUD on one record: you get save, edit, delete, cancel free, and it enforces sharing, CRUD and FLS automatically. Custom controller when the page isn't tied to a single record, or you need complete control — but it only respects sharing if you declare with sharing. Extension when you want standard behaviour plus extra logic; its constructor must accept an ApexPages.StandardController.

2 What is view state and how do you fix "Maximum view state size limit exceeded"?Hard

Every <apex:form> carries an encrypted hidden field holding all the controller state needed to rebuild the page on postback, capped at 170 KB.

Fixes: mark large collections transient so they're excluded; query only the fields and rows you actually render; paginate with StandardSetController; use <apex:actionRegion> so only part of the form posts back; avoid multiple forms; and move heavy interaction to JS Remoting (@RemoteAction), which bypasses view state entirely. Inspect it in the Developer Console's View State tab.

3 Where is Visualforce still the right choice in a Lightning org?Medium

PDF generation (renderAs="pdf") — still the simplest native way to produce a branded quote or invoice. Visualforce email templates for rich, data-driven emails. File downloads via contentType="text/csv". And maintaining the thousands of pages already running perfectly well in mature orgs. Everything user-facing and new should be LWC.

4 What is @RemoteAction and why is it faster?Medium

JS Remoting: a global static Apex method called directly from JavaScript via Visualforce.remoting.Manager.invokeAction. It sends only the arguments and returns only the result — no view state, no full page postback, so it's dramatically faster and lighter than an <apex:actionFunction> rerender.

The trade-off: you lose the automatic binding and must update the DOM yourself. Also, being static, it has no access to controller instance state.

5 How do you prevent XSS in Visualforce?Hard

Output is HTML-escaped by default — the danger is escape="false" on <apex:outputText>, which people add to render stored HTML and thereby open an injection hole.

Treat {!$CurrentPage.parameters.x} as untrusted, and apply the right encoder for the context: HTMLENCODE(), JSENCODE(), URLENCODE() or JSINHTMLENCODE() when a value lands inside a script block within HTML. In Apex, bind SOQL variables and use String.escapeSingleQuotes() for any dynamic query.

6 Component event vs application event in Aura — and what replaced them?Medium

A component event bubbles up the containment hierarchy, so only ancestors can handle it — decoupled and predictable, and the right default. An application event broadcasts to every component that registered a handler, regardless of hierarchy — powerful but very hard to trace.

In LWC these became CustomEvent (component) and Lightning Message Service (application), with LMS adding a declared schema and cross-technology reach.

7 Can an LWC contain an Aura component? What does that mean for migration?Easy

No — Aura can contain LWC, never the reverse. So migration proceeds leaf-first: rewrite the innermost components as LWC, keep the Aura shell hosting them, and replace the shell last. During the transition the two layers communicate through LMS, or through the Aura component passing @api properties down and listening for the LWC's custom events.

8 What still requires Aura today?Hard

A shrinking list: being the target of standard__component navigation (you can't navigate directly to an LWC); Lightning Out, which needs an Aura dependency app to embed Lightning in an external site or Visualforce page; a few console API interactions; and some quick-action behaviours around programmatically closing the action panel. Everything else should be LWC — and an Aura wrapper hosting an LWC is the standard bridge.

Quick check

1. Your Visualforce page throws "Maximum view state size limit exceeded". First fix?
View state carries all non-transient controller state, capped at 170 KB. transient excludes a variable entirely.
2. You need a printable, branded invoice PDF. What do you reach for?
This remains one of the few areas where Visualforce is still the standard native answer.
3. Can you put an Aura component inside an LWC?
Aura can host LWC; LWC cannot host Aura. This one-way rule drives every migration plan.
