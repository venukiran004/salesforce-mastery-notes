Einstein, AI & Data Cloud

The AI layer every Salesforce role is now expected to understand — predictive Einstein, generative Prompt Builder and Agentforce, the Trust Layer that makes them safe, and the Data Cloud underneath.

🔄
Fast-moving area Salesforce renames and repackages AI products frequently. Learn the concepts and the architecture — grounding, the Trust Layer, predictive vs generative — because those persist even when the product names change. Always confirm current feature availability and licensing against official documentation.

The AI landscape

📊
The honest constraint Predictive Einstein learns from your history. Thin, inconsistent or biased data produces a confidently wrong model. If the field you want to predict has been filled inconsistently for two years, fix the data quality before enabling the feature — otherwise you'll ship a model users stop trusting after a week.

Generative AI & Prompt Builder

Prompt Builder lets an admin create a reusable, grounded prompt template that produces text using your live Salesforce data — no code and no model training.

How a grounded prompt is assembled and answered
Prompt template typeUsed for
Field GenerationPopulate a field with generated text (a summary, a description) shown in a Dynamic Form
Email GenerationDraft an email grounded in the record, shown in the email composer for review
Record SummarySummarise a record and its related data on the page
Flex / CustomCalled from Flow, Apex or an agent action with your own inputs

Grounding sources

  • Record merge fields — fields from the record and its parents.
  • Related lists — recent cases, open opportunities, past orders.
  • Flow — call a flow to fetch or compute anything the template can't reach directly.
  • Apex — an @InvocableMethod for complex retrieval.
  • Data Cloud — unified profile and engagement data from outside the CRM.
  • Knowledge / retrieval — search relevant articles and inject them (RAG).

Writing a prompt that behaves

✅ Do

  • State the role, task, audience and tone explicitly
  • Give hard constraints: length, format, language
  • Say what to do when data is missing — "if no recent case, say so; do not invent one"
  • Provide an example of a good output
  • Ground with real fields rather than asking the model to recall
  • Test against edge-case records: empty, enormous, non-English

❌ Don't

  • Assume the model knows your business terms — define them
  • Merge in more data "just in case" — it costs tokens and dilutes focus
  • Let generated text write to a record without human review, for anything customer-visible
  • Put credentials, secrets or instructions-to-ignore-rules in a template
  • Forget FLS — merge fields respect the running user's access, so output varies by user

Agentforce — agentic AI

An agent goes beyond generating text: it decides which actions to take and executes them.

Building blockMeaning
AgentThe configured assistant, with a role and a set of topics
TopicA job the agent can handle, described in natural language with scope and instructions
ActionWhat it can actually do — a Flow, an Apex invocable method, a prompt template, an API call, or a standard action
InstructionsNatural-language rules governing when to use which action, and what never to do
GroundingThe CRM/Data Cloud/Knowledge context it reasons over
EscalationThe handoff path to a human when confidence is low or the customer asks
🛑
Design agents defensively An agent's actions run with real permissions against real data. Give it a dedicated user with least privilege, prefer read and draft actions over destructive ones, require confirmation before anything irreversible, log every action, and define the escalation path before go-live. "The agent deleted it" is not a defence.

The Einstein Trust Layer

This is the architecture answer interviewers want, because it addresses the first objection every customer raises: "is our data going into a public model?"

ControlWhat it does
Secure data retrievalGrounding respects the running user's sharing and FLS — the prompt can only include data that user could see
Data maskingPII is replaced with placeholders before the prompt leaves the platform, and restored in the response
Zero data retentionContractual commitment that the model provider does not store your prompts or use them for training
Toxicity detectionScores generated output and blocks harmful content
Prompt defenceSystem instructions that resist prompt-injection attempts
Audit trail & feedbackPrompts, responses and user feedback are logged for review

Data Cloud in one page

Data Cloud ingests data from many systems, resolves it into a unified profile, and makes it available to Salesforce in real time — including as grounding for AI.

ConceptMeaning
Data StreamAn ingestion pipeline — CRM, S3, web/mobile SDK, MuleSoft, or a zero-copy share from a warehouse
Data Lake Object (DLO)Raw ingested data as landed
Data Model Object (DMO)Data mapped to the canonical model, so sources become comparable
Identity ResolutionMatch and reconciliation rules that merge records into one Unified Profile
Calculated InsightsMetrics computed across the whole dataset — lifetime value, engagement score
Segments & ActivationsAudiences pushed to Marketing Cloud, ads or back into CRM
Zero CopyQuery Snowflake/BigQuery/Databricks in place, without duplicating the data

Why it matters for AI: generative output is only as good as its grounding. Data Cloud is how an agent knows about web behaviour, purchases and support history that never lived in the CRM.

What a developer actually builds

// Invoke a prompt template from Apex (ConnectApi.EinsteinLLM)
ConnectApi.EinsteinPromptTemplateGenerationsInput input =
    new ConnectApi.EinsteinPromptTemplateGenerationsInput();
input.isPreview = false;

ConnectApi.WrappedValue recordValue = new ConnectApi.WrappedValue();
recordValue.value = caseId;
input.inputParams = new Map<String, ConnectApi.WrappedValue>{
    'Input:Case' => recordValue
};

ConnectApi.EinsteinPromptTemplateGenerationsRepresentation result =
    ConnectApi.EinsteinLLM.generateMessagesForPromptTemplate('Case_Summary_Template', input);
String summary = result.generations[0].text;

// Expose an Apex action to an agent or a prompt template
public class CreateFollowUpTask {
    @InvocableMethod(label='Create follow-up task'
                     description='Creates a task on the case owner'
                     category='Service')
    public static List<Id> run(List<Request> requests) {
        List<Task> tasks = new List<Task>();
        for (Request r : requests) {
            tasks.add(new Task(WhatId = r.caseId, Subject = r.subject,
                               ActivityDate = Date.today().addDays(1)));
        }
        insert tasks;                       // bulk-safe: one DML
        List<Id> ids = new List<Id>();
        for (Task t : tasks) ids.add(t.Id);
        return ids;
    }
    public class Request {
        @InvocableVariable(required=true) public Id caseId;
        @InvocableVariable(required=true) public String subject;
    }
}

The pattern to notice: your existing Apex and Flow skills are the integration point. Agents and prompts call invocable actions — so writing safe, bulkified, well-described invocables is the developer's main job in an AI project.

Interview questions

1 Predictive vs generative AI in Salesforce — give an example of each.Easy

Predictive answers "what is likely?" from your historical data — Einstein Opportunity Scoring ranking deals by close likelihood, or Prediction Builder forecasting churn. It's trained on your records and outputs a score or a value.

Generative answers "write this" using a large language model grounded in your data — Prompt Builder drafting a case summary or a customer email. It isn't trained on your data; it's given your data at prompt time.

2 A customer asks "is our data used to train OpenAI's models?" What do you say?Hard

Explain the Einstein Trust Layer. Data sent for generation is subject to zero-retention agreements with the model providers — prompts and responses aren't stored or used for training. Before leaving the platform, PII is masked and restored afterwards. Grounding respects the running user's sharing and FLS, so a prompt can never include data that user couldn't already see. Output passes toxicity checks, and prompts, responses and feedback are audited.

3 What is "grounding" and why does it determine output quality?Medium

Grounding is injecting your actual data into the prompt — record fields, related lists, Knowledge articles, Data Cloud profile data. The model has no knowledge of your org; without grounding it will produce plausible, generic and often wrong text.

So output quality is mostly a data problem, not a prompt-wording problem: if the case has no description and no related history, no amount of prompt engineering produces a useful summary.

4 Einstein Prediction Builder has poor accuracy. What do you investigate?Hard

Almost always data, not the model. Check: is there enough history (hundreds of examples of each outcome)? Is the target field filled consistently, or did the process change last year? Is the class balance extreme (99% one outcome)? Is there leakage — a field that's only populated after the outcome is known, which the model will latch onto? Are the predictors actually available at prediction time? And has the business changed such that old patterns no longer hold?

5 How would you safely let an agent act on customer records?Hard

Give the agent a dedicated user with least-privilege permissions — it inherits that user's object, field and record access, so the sharing model does the heavy lifting. Prefer read and draft actions; require explicit confirmation before anything irreversible; scope each Topic narrowly with instructions on what it must never do; log every action taken; and define the escalation to a human path up front. Then test adversarially — try to talk it into doing something out of scope.

6 What's the developer's role in an Agentforce project?Medium

Building the actions the agent can take, and the grounding it reasons over. In practice that's Flows and @InvocableMethod Apex — bulk-safe, well-described (the label and description are what the model reads to decide when to call it), with validated inputs and clear error handling.

Plus the usual engineering: security review of what the agent's user can reach, tests for the invocables, and observability so you can see what the agent actually did.

7 What problem does Data Cloud solve that a custom object can't?Hard

Scale and identity. It ingests billions of rows of behavioural and transactional data from many systems — far beyond what you'd put in CRM objects — and resolves them into a single Unified Profile through configurable match and reconciliation rules.

It also supports zero-copy federation of a warehouse, so you query Snowflake or BigQuery in place rather than duplicating it. For AI, that unified profile is the grounding that lets an agent reason about web behaviour and purchase history the CRM never held.

8 The business wants AI on everything. How do you choose the first use case?Medium

Pick something with high volume, low risk and a measurable baseline — case summarisation or reply drafting is the classic first project: agents do it hundreds of times a day, output is reviewed by a human before it reaches a customer, and you can measure handle time before and after.

Avoid starting with anything customer-facing and autonomous, or anything grounded in data you know is poor. And agree the success metric before you build, or the project becomes a demo nobody adopts.

Quick check

1. A generated case summary invents details that aren't in the record. Most likely cause?
LLMs fill gaps plausibly. Ground with real fields and instruct explicitly: "if there is no recent case, say so; do not invent one."
2. Which Trust Layer control stops a prompt containing data the user shouldn't see?
The prompt is assembled in the user's context, so it can only include records and fields that user could already access.
3. What does an Agentforce "Action" usually map to for a developer?
Agents execute invocable actions — which is why writing safe, well-described, bulkified invocables is the core developer task in an AI project.
