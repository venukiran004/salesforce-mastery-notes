Admin & configuration

1 Lookup vs Master-Detail — give five differences.Easy
  1. Required: master-detail is mandatory; lookup is optional.
  2. Delete: master-detail cascades (children deleted); lookup leaves the child (or blocks the delete).
  3. Ownership & sharing: a detail record has no Owner and inherits sharing from the master.
  4. Roll-up summary: only master-detail supports it.
  5. Limits: 2 master-detail vs 40 lookups per object; reparenting is disallowed by default on master-detail.

See Relationships.

2 When would you choose Custom Metadata over a Custom Setting?Medium

Choose Custom Metadata Types when the configuration records must deploy with your metadata — integration endpoints, business rules, mapping tables. They're deployable, packageable, queryable without consuming SOQL limits, and can have relationships.

Choose a Hierarchy Custom Setting only when you need per-user or per-profile values — the classic case being a trigger bypass switch you can flip for one integration user during a data load.

3 A duplicate rule isn't firing for records created by an integration. Why?Medium

Several possibilities: the rule's conditions exclude those records; the integration passes DmlOptions.duplicateRuleHeader.allowSave = true; the matching rule is still indexing after activation; the rule is set to run on Create only and this is an update; or another duplicate rule on the object takes precedence (only one runs per operation).

4 Explain the difference between a Queue and a Public Group.Easy

A Queue can own records — members pull work from it, and it can be an approver. A Public Group cannot own anything; it's a bundle of users/roles used to grant access in sharing rules, list view visibility and folder sharing. Mnemonic: queues own, groups grant.

5 How do you find all Accounts with no Opportunities?Medium

Report on Accounts with a cross filter "without Opportunities". Alternatively create a custom report type "Accounts with or without Opportunities" and filter Opportunity ID equals "". In Apex: SELECT Id FROM Account WHERE Id NOT IN (SELECT AccountId FROM Opportunity).

6 Walk me through the Lead conversion process and its gotchas.Medium

Converting a Lead creates an Account, a Contact and optionally an Opportunity, marks the Lead IsConverted = true and makes it read-only. Existing Account/Contact records can be matched instead of created.

Gotchas: custom Lead fields must be explicitly mapped or the data is lost; data types must match; triggers fire on all four objects in one transaction (watch your limits); detect it in Apex with lead.isConverted && !oldLead.isConverted; and validation rules on the target objects can block the conversion in confusing ways.

7 Design a Web-to-Lead flow that handles 500+ leads a day.Hard

Web-to-Lead is capped at 500 leads/day — overflow goes to the default lead owner with a warning email, so above that volume you should switch to the REST API (or a middleware layer) posting Leads directly. Either way: add reCAPTCHA, set lead_source, run an assignment rule to route by territory, add an auto-response rule for acknowledgement, and activate duplicate/matching rules set to "Allow with alert + Report" so uploads never hard-fail.

8 What are the four action buckets of an approval process?Easy

Initial Submission (usually locks the record), Final Approval, Final Rejection and Recall. Each can run a Field Update, Email Alert, Task or Outbound Message.

9 Difference between a Validation Rule and a Duplicate Rule?Easy

A validation rule checks the values within the record being saved and blocks the save when its formula returns TRUE. A duplicate rule compares the record against other records using a matching rule, and can block or just warn. Validation rules run at step 6 of the order of execution; duplicate rules at step 7.

10 Email-to-Case: On-Demand vs Standard?Medium

On-Demand needs no software — email is routed through Salesforce. It's the default choice. Standard requires an email agent installed behind your firewall, which keeps message bodies on your own servers and supports larger attachments; choose it only for strict compliance requirements.

11 Roll-up summary alternatives when you only have a Lookup?Medium
  1. A record-triggered flow on the child that recalculates the parent.
  2. An Apex trigger with an aggregate query (handle insert, update including reparenting, delete and undelete).
  3. Convert the lookup to master-detail if the data model allows it.
  4. A scheduled Batch Apex recalculation for non-real-time needs.
  5. A declarative AppExchange rollup tool.
12 When would you use a Record Type versus separate objects?Medium

Use record types when the data is fundamentally the same entity with different processes, picklist values or layouts — e.g. B2B vs B2C Opportunities that both roll into one pipeline report. Use separate objects when the fields barely overlap, security differs sharply, or you'd never report across them together. Over-using record types leads to bloated layouts; over-using objects makes reporting painful.

Security & sharing

13 Explain the record access hierarchy in order.Medium

OWD (the restrictive baseline) → record ownership → role hierarchy → sharing rules (owner-based and criteria-based) → manual sharing → teams → territories → Apex managed sharing → implicit sharing. Everything after OWD is additive; the only subtractive control is a Restriction Rule.

14 Profile vs Permission Set vs Permission Set Group vs Role.Easy

Profile — exactly one per user, the baseline of what they can do. Permission Set — many per user, adds capability, never removes. Permission Set Group — a bundle for a job function, and a Muting Permission Set inside it can subtract. Role — nothing to do with permissions; it controls record visibility through the hierarchy.

15 Does with sharing enforce field-level security?Hard

No. It only enforces record-level sharing — which rows the user can see. FLS and object CRUD need explicit enforcement: WITH USER_MODE on queries, AccessLevel.USER_MODE on DML, Security.stripInaccessible(), or describe checks like isAccessible(). This is the single most common security-review failure.

16 A user can see a record nobody can explain. How do you diagnose it?Medium

Open the record and click the Sharing button — it lists every reason for access. Then check: View All / Modify All on the object, View All Data, the role hierarchy, criteria-based sharing rules, implicit sharing from a parent Account, team membership, and Apex shares (SELECT UserOrGroupId, RowCause FROM AccountShare WHERE AccountId = …).

17 What happens to manual shares when the record owner changes?Hard

Manual shares (RowCause = 'Manual') are deleted automatically. Apex managed shares with a custom Apex Sharing Reason survive an owner change — which is precisely why you define one instead of using Manual in code.

18 OWD is Private. How do you give a support team read access to all Cases?Medium

Options, in order of preference: (1) a criteria-based or owner-based sharing rule sharing Cases with a Support public group; (2) place the team under a role branch that already has access; (3) grant View All on Case via a permission set if they genuinely need every case. Avoid View All Data — it grants everything on every object.

19 What is implicit sharing?Hard

Built-in, non-configurable sharing between Accounts and their child Contacts, Cases and Opportunities. Access to a child grants Read on the parent Account; access to an Account grants access to children according to the Account's related-object settings. It can't be turned off and explains many "why can they see this?" mysteries.

20 Restriction Rule vs Scoping Rule?Medium

A Restriction Rule actually removes access that sharing granted — real security, applied to list views, reports, SOQL and the API. A Scoping Rule only changes the default filter a user sees; they can still switch it. Scoping is UX, restriction is security.

Apex

21 When would you use a Set instead of a List?Easy

When you need uniqueness or fast membership tests. Set.contains() is O(1); List.contains() is O(n) and will cause a CPU timeout inside a loop over thousands of records. Sets are also the natural container for collecting Ids to use in WHERE Id IN :ids.

22 Explain SOQL vs SOSL with a scenario for each.Easy

SOQL queries one object (plus relationships) in the database — "all open Cases for Account X created this month". SOSL searches the text index across many unrelated objects — "find 'acme' in Accounts, Contacts, Cases and Leads for a global search box". Limits differ: 100 SOQL / 50,000 rows vs 20 SOSL / 2,000 records.

23 How do you query a parent field and a child list in one go?Easy 
SELECT Id, Name, Owner.Email,                    // child → parent, dot notation, 5 levels
       (SELECT LastName FROM Contacts),          // parent → child, subquery, 1 level
       (SELECT Amount__c FROM Invoices__r)       // custom child relationship uses __r
FROM Account WHERE Id IN :accIds
24 DML statement vs Database method — when do you use each?Medium

insert list; is all-or-nothing and throws a DmlException — right when everything must succeed together. Database.insert(list, false) allows partial success and returns SaveResult[] so you can log the failures and continue — right for bulk loads and integrations. Database methods also accept DMLOptions for assignment rules, duplicate rules and email headers.

25 What is a wrapper class and when have you used one?Medium

A custom class combining an sObject with extra data that doesn't exist as a field — a selection checkbox, a computed score, data from a second object. Typical use: an LWC datatable with checkboxes and a calculated "health" label, returned from Apex with @AuraEnabled members. See wrapper classes.

26 How do you sort a List of custom objects by a custom rule?Medium

Implement Comparable and its Integer compareTo(Object other) method (return −1, 0 or 1), then call list.sort(). For sObjects, use ORDER BY in SOQL where possible; for multiple sort strategies over the same type, build a Map keyed by the sort value or use a comparator wrapper.

27 Why can't you catch a LimitException?Medium

Because the platform must be able to terminate a runaway transaction unconditionally — if you could catch it, you could keep consuming resources. Prevent instead: check Limits.getQueries() before expensive operations and hand off to async when approaching the limit.

28 Explain static variables in Apex and one practical use.Medium

A static variable exists once per transaction and is shared by every instance of the class. It is not shared between transactions, users, or async jobs (a @future call starts fresh). Practical uses: recursion guards in triggers, and caching an expensive describe or configuration lookup for the duration of the transaction.

29 What is Dynamic Apex and when is it worth the complexity?Hard

Code that discovers metadata at runtime — Schema.getGlobalDescribe(), field describes, Database.query() with a built string, sObject.get()/put(), Type.forName(). Worth it for genuinely generic utilities (a field-set-driven table, an object-agnostic audit framework, a plug-in architecture driven by Custom Metadata). Not worth it when you know the object — it costs CPU time and readability, and opens SOQL injection risk if you don't bind or escape.

30 How do you prevent SOQL injection?Medium

Use bind variables (WHERE Name = :userInput) — they can't be injected. If you must build a string, use Database.queryWithBinds() with a bind map, or String.escapeSingleQuotes() as a minimum. Also validate that dynamic object/field names come from a whitelist, since escaping doesn't protect the FROM clause.

31 What's a MIXED_DML_OPERATION error and how do you fix it?Medium

You performed DML on a setup object (User, Group, PermissionSetAssignment, UserRole…) and a non-setup object in the same transaction. Fix by moving one of them into an async context (@future/Queueable), or in tests by wrapping the setup DML in System.runAs(new User(Id = UserInfo.getUserId())) { … }.

32 Explain with sharing, without sharing and inherited sharing.Medium

with sharing enforces the running user's record access. without sharing runs in system context. inherited sharing takes the caller's mode and defaults to with sharing when entered directly — making it the safest default for reusable service classes. A class with no keyword defaults to without sharing when it's the entry point, which is why omitting it is a bug, not a style choice.

Async Apex & testing

33 Compare @future, Queueable, Batch and Schedulable.Medium

@future — primitives only, no chaining, no job Id. Legacy. Queueable — accepts sObjects and complex types, returns a job Id, chainable, supports Finalizers. The modern default. Batch — up to 50 M records via QueryLocator, fresh limits per 200-record chunk, Database.Stateful for state. Schedulable — cron-based; usually just launches a Batch or Queueable.

34 Why can't you call a callout after DML, and what are the two fixes?Medium

Salesforce won't hold an open database transaction while waiting on an external system, so it throws "You have uncommitted work pending". Fix by moving the callout to @future(callout=true) or a Queueable implements Database.AllowsCallouts — both run after commit. For flows, use an asynchronous path.

35 What is a Transaction Finalizer and what problem does it solve?Hard

A class implementing Finalizer, attached inside a Queueable with System.attachFinalizer(). It runs in its own transaction after the job finishes — including after an unhandled exception. Before finalizers, an unhandled exception rolled back the job's transaction along with any error log you'd inserted, leaving you blind. A finalizer can also enqueue one retry.

36 How many records can Batch Apex process, and what determines the chunk size?Easy

Up to 50 million records via Database.QueryLocator. Scope size is set in Database.executeBatch(batch, size), from 1 to 2,000, defaulting to 200. Use a smaller scope when each record does heavy work or a callout, because each chunk gets its own governor limits but callouts are capped at 100 per chunk.

37 Why does Test.stopTest() matter?Easy

It restores governor limits and forces any asynchronous work queued since startTest() to execute synchronously. Assertions on async results must come after stopTest(), or you'll be asserting on work that hasn't run.

38 How do you test a class that makes an HTTP callout?Medium

Implement HttpCalloutMock (or use StaticResourceCalloutMock) and register it with Test.setMock(HttpCalloutMock.class, new MyMock()) before invoking the code. Write separate tests for 200, 4xx and 5xx responses — the failure paths are what mocks make testable. For SOAP, implement WebServiceMock.

39 Is 75% coverage a quality target?Easy

No — it's a deployment gate. Coverage measures which lines executed, not whether behaviour is correct. A loop calling a method 100 times with no assertions gives high coverage and zero confidence. Aim for meaningful assertions, bulk tests with 200 records, negative paths, and runAs tests for permissions.

40 Why avoid SeeAllData=true?Easy

It makes tests depend on org data, so they pass in your sandbox and fail in production (or after someone deletes a record). Create your own data with a TestDataFactory. The rare exceptions are objects tests can't create, such as the standard Pricebook — and even there, Test.getStandardPricebookId() is the better answer.

Lightning Web Components

41 List the lifecycle hooks in firing order for a parent with a child.Medium

Parent constructor → parent connectedCallback → parent render → child constructor → child connectedCallback → child render → child renderedCallback → parent renderedCallback. Rendering flows top-down; renderedCallback fires bottom-up.

42 Your renderedCallback causes an infinite loop. Why and how do you fix it?Medium

You changed a reactive property inside it, which triggers a re-render, which calls renderedCallback again. Fix with a boolean guard (if (this.initialised) return;), or move the work to connectedCallback if it doesn't need the DOM.

43 Why doesn't the UI update after this.items.push(x)?Easy

LWC reactivity for fields is reference-based: mutating an array doesn't change its reference. Reassign — this.items = [...this.items, x] — or decorate the field with @track to make its internals deeply reactive.

44 What is Shadow DOM and name three consequences.Medium

An encapsulated DOM tree attached to the component's host element. Consequences: (1) CSS doesn't leak in or out, so global styles won't hit your markup; (2) document.querySelector can't see inside — use this.template.querySelector() or lwc:ref; (3) events are retargeted at the boundary, so listeners outside see the host as the target. Also: third-party libraries expecting global DOM access may need Light DOM.

45 All four communication patterns — when do you use each?Medium

Parent→Child: @api property or public method. Child→Parent: CustomEvent with a detail payload. Siblings: bubble to the common parent, or use LMS. Anywhere on the page / across LWC, Aura and Visualforce: Lightning Message Service. Pub-sub is the legacy predecessor of LMS and is LWC-only.

46 @wire vs imperative Apex.Easy

@wire is reactive and automatic, requires cacheable=true, returns read-only data and cannot perform DML. Imperative calls run only when invoked, allow DML, and give mutable results plus full control over loading and error states. Reads that follow a record → wire; writes and button clicks → imperative.

47 Your wired list doesn't refresh after a save. Fix?Medium

Store the entire wired result (not just data) and call refreshApex(this.wiredResult). For LDS-managed records also call notifyRecordUpdateAvailable([{recordId}]). The wire cache is only invalidated automatically when a reactive parameter changes.

48 Why use Lightning Data Service over Apex?Medium

Shared client-side cache (one server request serves every component), automatic FLS and sharing enforcement, automatic UI refresh across all components when a record changes, and no Apex or test class to maintain. Drop to Apex only when you need complex queries, aggregates, multi-record transactions or unsupported objects.

49 What are the rules for the key in for:each?Easy

It's mandatory, goes on the first element inside the loop, and must be a unique primitive — never an object, and avoid the array index if the list can reorder. Without a stable key LWC reuses the wrong DOM nodes, producing subtle rendering bugs.

50 How do you securely expose Apex to LWC?Hard

Declare the class with sharing, mark methods @AuraEnabled (cacheable=true for reads), enforce FLS with WITH USER_MODE / insert as user / Security.stripInaccessible, validate all inputs, bind SOQL variables, and throw AuraHandledException so the client gets a clean message instead of a stack trace. Remember @AuraEnabled methods run in system context for FLS by default — nothing is enforced for you.

51 Can an LWC contain an Aura component?Easy

No. Aura can contain LWC, but not the reverse. This one-way rule dictates that migrations proceed leaf-first: convert the innermost components to LWC, keep the Aura shell, and replace the shell last.

52 How do you get real-time updates into an LWC?Hard

Subscribe to a Platform Event or Change Data Capture channel with lightning/empApi in connectedCallback, and unsubscribe in disconnectedCallback. Never poll on a setInterval — it burns API calls and doesn't scale.

Integration

53 Inbound vs outbound — what changes in your design?Easy

Inbound: Salesforce is the server. You configure a Connected App, an OAuth flow, a least-privilege integration user, and watch your daily API allocation. Outbound: Salesforce is the client. You configure a Named Credential, handle the 100-callout/120-second limits, and deal with the DML-before-callout restriction.

54 Name the six integration patterns with an example each.Hard
  1. Request & Reply — live credit check before saving an Opportunity.
  2. Fire & Forget — publish an event when an order ships.
  3. Remote Call-In — the web store creates a Lead via REST.
  4. Batch Data Sync — nightly 2 M product load via Bulk API.
  5. UI Update on Data Change — console refreshes via empApi.
  6. Data Virtualisation — SAP invoices via Salesforce Connect.

See Integration Patterns.

55 Why is upsert-by-External-Id the backbone of integrations?Medium

Because it makes calls idempotent. The external system says PATCH /sobjects/Account/Legacy_Id__c/A-1001 without ever storing a Salesforce Id. Replaying the same message after a timeout updates rather than duplicating — which is exactly what you need when networks fail.

56 401 vs 403 vs 404 — what does each tell you?Easy

401 = unauthenticated ("who are you?") — expired or missing token; refresh it. 403 = authenticated but not allowed — missing object/field permission, or REQUEST_LIMIT_EXCEEDED. 404 = wrong URL, wrong API version, or the record doesn't exist / isn't visible to you.

57 Platform Events vs Change Data Capture.Medium

Platform Events: you define the payload and choose when to publish — a business event like "Order Shipped". CDC: Salesforce publishes automatically on every record change with the changed fields — a data event, ideal for replicating to a data lake. Both retain 72 hours and deliver at least once.

58 When is an Outbound Message still the right tool?Medium

When you need guaranteed delivery with automatic retry for 24 hours and zero code, and the receiver can accept SOAP and return <Ack>true</Ack>. Its limits: SOAP/XML only, one-way, single object, and tied to Workflow/Approval actions. For new work, Platform Events are usually better.

59 Composite vs Composite Batch vs sObject Tree vs Graph.Hard

/composite — up to 25 chained subrequests that can reference each other (@{ref.id}), optionally all-or-none. /composite/batch — 25 independent subrequests, no referencing. /composite/tree — up to 200 records of one object tree, nested parent/child inserts. /composite/graph — up to 500 records across 75 graphs, each graph committing independently.

60 When would you use Salesforce Connect instead of copying data in?Medium

When the data is large, rarely accessed, and owned elsewhere — 12 M SAP invoices you occasionally look at. No storage cost, never stale. The trade-off: no triggers or flows on external objects, limited reporting, and every page view depends on the external system being up.

61 Which OAuth flow for a nightly server-to-server job, and why?Hard

JWT Bearer. It uses a certificate rather than a password, needs no user interaction, survives password changes and MFA policies, and the private key can live in a secrets vault. Client Credentials is the simpler alternative when you can nominate a run-as user on the Connected App. Username-Password is deprecated and blocked by default.

62 Named Credential vs Remote Site Setting.Easy

A Remote Site Setting only whitelists a URL — you still manage tokens and headers yourself. A Named Credential stores the endpoint and the authentication, injects the auth header automatically, refreshes OAuth tokens, and keeps secrets out of code. Use req.setEndpoint('callout:My_Credential/path').

Scenario & design

63 Design: "When an Opportunity closes, create an order in SAP and show live order status in Salesforce."Hard

Two patterns. Order creation is Fire and Forget (outbound); status display is Data Virtualisation.

  • Record-triggered Flow (after save) on Closed Won publishes Order_Ready__e.
  • A platform-event trigger enqueues a Queueable (Database.AllowsCallouts) that POSTs to SAP via a Named Credential and writes the SAP order number back.
  • Idempotency: send the Opportunity Id as the idempotency key so a retry never double-creates.
  • Retry 3 times with growing delay on 5xx; permanent failures write Integration_Error__c and alert.
  • Status: a Salesforce Connect OData external object SAP_Order__x with an Indirect Lookup to Account.
  • Auth: JWT Bearer via an External Credential; a dedicated integration user with a least-privilege permission set.
  • Monitoring: a report and dashboard on today's integration errors, plus an email alert.
64 Your org has 15 flows and 3 triggers on Account and saves are timing out. What do you do?Hard
  1. Measure first — a debug log's CUMULATIVE_LIMIT_USAGE shows which component burns CPU, SOQL and DML.
  2. Consolidate the triggers into one per object with a handler, so execution order is deterministic.
  3. Consolidate the flows to one before-save and one after-save record-triggered flow, branching internally with Decisions.
  4. Move same-record field updates to before-save — this alone often removes several DML operations and a recursion cycle.
  5. Tighten entry criteria to "only when a record is updated to meet the condition".
  6. Remove duplicated logic where a flow and a trigger do the same job.
  7. Move non-urgent work async (Queueable or a scheduled path).
  8. Check for SOQL/DML in loops inside both flows and Apex.
  9. Agree a governance rule: one automation tool per concern per object, documented.
65 You must load 5 million records into a custom object with triggers. What's your plan?Hard
  1. Bulk API 2.0 with upsert on an External Id, in a sandbox first to measure throughput.
  2. Verify the trigger is bulk-safe — it will run in chunks of 200; no SOQL/DML in loops.
  3. Bypass unnecessary automation for the load user with a hierarchy Custom Setting switch, and document turning it back on.
  4. Defer sharing recalculation if the object has sharing rules, and consider deferring roll-ups.
  5. Sort the file by parent Id to avoid UNABLE_TO_LOCK_ROW from parallel batches; use serial mode if locking persists.
  6. Load off-peak, in tranches, monitoring the job status and failed-results file.
  7. Reprocess failures from failedResults, then run a reconciliation count.
  8. Re-enable automation and, if needed, run a Batch Apex job to apply the skipped logic to the loaded records.
