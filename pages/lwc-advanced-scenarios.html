LWC Data & Events — 100 Scenarios

Wire service and cache invalidation, imperative Apex, LDS, GraphQL, component communication, navigation, error shapes and client-side security.

📚
How to use this Answer out loud in ninety seconds, then open the answer. Concepts on LWC Data & Events and its Advanced section.

Wire service (1–16)

1 A wired property never populates.Easy

Usually a reactive parameter that is still undefined — the wire does not fire until all $-prefixed parameters have values.

Check that recordId is actually set (it is injected only on record pages), and render a loading state until the data arrives.

2 $recordId versus recordId in a wire.Easy

The $ makes it reactive: the wire re-runs when the value changes. Without it, the value is captured once at creation.

Forgetting the $ produces a component that never refreshes when the parent changes the input.

3 You changed data in Apex and the wire still shows the old value.Hard

The wire result is cached. For @wire(apexMethod), call refreshApex(this.wiredResult) — passing the whole wired object, not .data.

For @wire(getRecord), call notifyRecordUpdateAvailable([{recordId}]) so LDS knows that record is dirty.

4 refreshApex does nothing.Medium

You passed this.data instead of the full wired result object. refreshApex needs the object the wire handed you.

Use the function form of @wire and store the whole result in a field for exactly this reason.

5 Which refresh mechanism for which situation?Hard

Changed via LDS → nothing needed. Changed via Apex but read with getRecord → notifyRecordUpdateAvailable. Read with @wire(apex) → refreshApex. Called Apex imperatively → just call again.

Changed by another user → nothing client-side will know; subscribe to an event or accept staleness.

6 An Apex method cannot be wired.Easy

It must be @AuraEnabled(cacheable=true), which also means it must not perform DML.

If it writes, call it imperatively. The cacheable flag is a promise about side effects, not just a performance hint.

7 Two components wire the same Apex method with the same parameters.Medium

The result is served from cache, so you get one server call — which is a genuine benefit of wiring over imperative calls.

It also means refreshApex in one component refreshes the shared cache entry both are reading.

8 You need to wire with a parameter that is an object.Medium

Reactive object parameters work but re-fire whenever the reference changes — so spreading a new object on every render causes a request storm.

Prefer primitive reactive parameters, and construct them deliberately.

9 A wire fires repeatedly in a loop.Hard

Its reactive parameter is being reassigned on every render — commonly because it comes from a getter that builds a new object or array.

Compute the parameter once into a field when the inputs change, not in a getter.

10 You want the wire to re-run on demand.Medium

Either change a reactive parameter, or use refreshApex on the stored result.

There is no "re-run this wire" call — reactivity and explicit refresh are the two levers.

11 You need data before first render.Medium

Not possible — render happens first and the wire resolves afterwards. Design for a loading state.

If you truly cannot render without it, render nothing but a spinner until the data is present.

12 A wired error is an object you cannot read.Medium

LDS and Apex errors have different shapes — error.body can be an array, or contain output.fieldErrors, or be a plain message.

Normalise once in a shared reduceErrors utility and reuse it everywhere.

13 Should you use the property form or the function form of @wire?Easy

Function form when you need to react to the data (transform it, store the result for refreshApex, handle the error explicitly).

Property form only for the simplest cases where the template consumes it directly.

14 A wire works in the app and fails in a community.Medium

Guest or external users may lack access to the object or the Apex class, and some adapters are unavailable in some runtimes.

Test as the actual external persona and handle the error branch, which in a community is a realistic state rather than an edge case.

15 How do you avoid a wire on a component that is not visible?Medium

Render the component conditionally so it is not created, or gate the reactive parameter on an isActive property.

A wire in an inactive tab still costs a server call, which multiplies across a busy record page.

16 When is an imperative call better than a wire?Medium

When the call writes data, when it should only happen on user action, when you need the return value in sequence with other work, or when you need full control over timing and error handling.

Wires are for declarative reads that should stay fresh.

Imperative Apex & LDS (17–34)

17 An imperative call's error surfaces an internal class name.Easy

The Apex threw an unhandled exception. Throw AuraHandledException with a message written for the user, and log the detail server-side.

An unhandled exception is both unhelpful and an information leak.

18 You need to create a record with no Apex.Easy

createRecord from lightning/uiRecordApi, or lightning-record-edit-form for a full form.

LDS respects FLS and sharing automatically and updates the cache, so other components refresh themselves — which is why it beats Apex for simple CRUD.

19 lightning-record-edit-form hides a field you need.Medium

It respects field-level security, so an invisible field means the user lacks access — which is correct behaviour.

If it is a layout question rather than FLS, specify the fields explicitly rather than relying on the layout.

20 You need to update 50 records at once.Medium

LDS is single-record. Use an imperative Apex method taking a collection and doing one DML.

Then refresh: notifyRecordUpdateAvailable for the affected Ids, or refreshApex on the list wire.

21 When should you prefer LDS over Apex?Medium

Single-record CRUD, where you want automatic FLS, automatic cache updates and no code to test.

Apex when you need business logic, multiple records, complex queries, or aggregation — anything where the operation is more than reading or writing fields.

22 getRecord does not return a field you asked for.Medium

Either the user lacks FLS on it, or you requested it via layoutTypes rather than explicit fields and it is not on the layout.

Prefer explicit field imports — they are checked at compile time and do not depend on layout configuration.

23 Importing fields with @salesforce/schema — why bother?Easy

It creates a real dependency: the field cannot be deleted while the component references it, and typos fail at compile time.

String field names fail silently at runtime, which is strictly worse.

24 A field import blocks a field deletion you need.Easy

That is the feature working — it prevented you from breaking a component.

Remove the reference, deploy, then delete the field. The dependency is a safety net, not an obstacle.

25 You need to read a record the user cannot see.Hard

LDS will not do it — it respects sharing and FLS by design.

That requires deliberate elevation in Apex (without sharing, small and reviewed), with the justification documented. If you find yourself wanting this often, the sharing model is probably wrong.

26 A record form saves but a sibling component shows stale data.Medium

If the sibling uses LDS on the same record, it updates automatically. If it reads via Apex, it does not.

Handle the form's success event and call refreshApex on the sibling's wire, or have both components use LDS.

27 You need the picklist values for a field.Easy

getPicklistValues with a record type Id (from getObjectInfo) — which correctly returns only the values available for that record type.

Hard-coding picklist values in a component is a guaranteed future mismatch.

28 Dependent picklists in a custom component.Hard

getPicklistValues returns the controller values and the dependency mapping, which you then apply when the controlling field changes.

It is fiddly — lightning-record-edit-form handles dependencies for free, which is usually the better answer.

29 How do you handle a save that partially fails?Medium

Return structured results from Apex (success and failure per record) rather than throwing, and render which rows failed and why.

An all-or-nothing error message on a 50-row save gives the user no way forward.

30 A user double-clicks Save and you get two records.Medium

Disable the button on first click and re-enable on completion — and make the server-side operation idempotent with a client-generated key.

Client-side disabling alone is not sufficient under a slow connection.

31 You need optimistic UI updates.Hard

Update local state immediately, call the server, and roll back the local change on failure — with a clear message.

It improves perceived performance and adds real complexity, so reserve it for interactions where latency genuinely hurts.

32 Should a component call several Apex methods on load?Medium

Prefer one method returning a composite payload — fewer round trips and one error path.

Three sequential awaits on load is three latencies added together.

33 How do you cache an expensive Apex result client-side?Medium

A cacheable=true wire gives you the platform's cache for free, keyed by parameters.

For per-viewer convenience state (a chosen tab, a filter) localStorage is reasonable — wrapped in try/catch, because it can throw or come back empty.

34 An imperative call resolves after the component is destroyed.Medium

Harmless but it can mask bugs and waste work. Set a flag in disconnectedCallback and check it before updating state.

It also prevents confusing console errors in a console app where tabs open and close frequently.

GraphQL & querying (35–46)

35 When is the GraphQL wire adapter the right choice?Medium

Read-only data across several related objects, with pagination and filtering, honouring FLS and sharing — and it is the offline-capable adapter for mobile.

Essentially: when you would otherwise write an Apex method that only does SOQL.

36 GraphQL or Apex for a list view component?Medium

GraphQL if it is a straightforward filtered read with paging — no Apex to write, test or secure.

Apex if you need aggregation, complex joins beyond the adapter, or a payload shaped for a specific UI.

37 A GraphQL query returns nothing for some users.Easy

It respects sharing and FLS, so missing data usually means missing access — which is correct.

Verify by logging in as the user. This is a feature of the adapter, not a limitation.

38 You need aggregation in GraphQL.Medium

Support is limited compared with SOQL. For meaningful aggregates, use Apex with an aggregate query, or pre-compute into a field.

Trying to aggregate client-side over a paginated result set gives you a number that is wrong whenever there is more than one page.

39 Pagination with GraphQL.Medium

Cursor-based: request a page size and carry the cursor forward. It is one of the main reasons to choose the adapter — you do not implement paging yourself.

Keyset paging is also what keeps it fast at depth, unlike OFFSET.

40 Offline support for a mobile component.Hard

The GraphQL adapter plus whatever is primed to the device. Arbitrary Apex requires a server and will not work offline.

Design the component's data access around primed data, and handle the offline state explicitly. See offline architecture.

41 A GraphQL query is slow.Medium

Same underlying rules as SOQL: selectivity matters, and filters must be indexable.

Request fewer fields, filter more selectively, and page smaller. The adapter does not exempt you from the query optimiser.

42 You need data from an object the adapter does not support.Easy

Fall back to Apex. Adapter coverage expands over releases, so check the current state rather than assuming.

A mixed approach is fine — GraphQL where it fits, Apex where it does not.

43 How do you handle a GraphQL error?Medium

The wire gives you an errors structure that differs again from Apex and LDS shapes — add it to your normalising utility.

Render a useful message and a retry affordance; a silent empty state is indistinguishable from "no data".

44 Should the component build its query dynamically?Hard

Keep the shape static and parameterise the variables. A query assembled from user input is a client-controlled read.

If admins need configurability, drive it from design attributes with an allow-listed set of fields, not from arbitrary input.

45 Testing a GraphQL-wired component.Medium

Register a test wire adapter and emit a representative response — plus an error and an empty result.

Base the mock payload on a captured real response, or your test will pass against a shape the adapter never produces.

46 Migrating an Apex read to GraphQL — worth it?Medium

If the Apex only does SOQL, yes: less code, automatic security, free paging and offline capability.

If it does anything else, leave it. Migration for its own sake is churn.

Component communication (47–66)

47 A custom event does not reach the grandparent.Medium

By default events do not cross shadow boundaries. Either re-dispatch at each level, or set bubbles: true, composed: true.

Re-dispatching is usually better design — each component declares its own API rather than letting events leak through it.

48 Your event name with a colon does not work.Easy

Event names must be lowercase with no colons, hyphens are discouraged in the handler attribute mapping.

Use a single lowercase word or concatenation: rowselect, statuschange.

49 Should you use composed: true?Medium

Only when you genuinely need to cross shadow boundaries, and understand that it makes the event part of a much wider contract — anything above can listen.

Default to non-composed and re-dispatch deliberately.

50 Two unrelated components on a page need to talk.Medium

Lightning Message Service — it works across LWC, Aura and Visualforce and across the whole page.

Or, if the shared state is a record, have both wire it with LDS and let the cache be the channel, which needs no messaging at all.

51 Your LMS message updates the wrong console tab.Hard

LMS is a page-wide broadcast, so a second instance of your component in another tab receives it too.

Include a scope identifier (record Id, correlation key) in the payload and have subscribers ignore messages that are not theirs.

52 You need to subscribe to a platform event in a component.Medium

lightning/empApi — subscribe in connectedCallback, and unsubscribe in disconnectedCallback or you leak subscriptions.

Handle the error channel too, and remember events are not guaranteed to arrive in order.

53 How do you know another user changed the record?Hard

Nothing client-side will tell you. Publish a platform event or enable CDC and subscribe with empApi, then refresh.

Otherwise accept staleness and show a "last updated" timestamp, which solves the actual user concern more cheaply than real-time sync.

54 Parent needs to pass data to a child that is not rendered yet.Easy

Set it as a property in the template — the value is applied when the child is created.

Calling a method on a not-yet-rendered child returns null from querySelector, which is the usual symptom of reaching for the imperative approach too early.

55 A child needs to tell the parent "I am valid".Medium

Either a public validate() method the parent calls before submitting, or an event the child fires on every change carrying its validity.

The method is simpler for a form; the event keeps the parent's submit button state live without polling.

56 You need to pass an object through an event.Easy

Put it in detail. Across shadow boundaries the payload should be a plain, serialisable object — avoid passing live references the receiver might mutate.

Treat the event payload as a contract and keep it minimal.

57 An event handler fires twice.Medium

Either you added the listener twice (connectedCallback firing again without cleanup), or the event bubbles and two ancestors handle it.

Remove listeners in disconnectedCallback, and reconsider whether the event needs to bubble.

58 You need to open a record page from a component.Easy

NavigationMixin with a standard__recordPage page reference — never a hard-coded URL, which breaks across environments, communities and My Domain changes.

Page references also work correctly in the mobile app and in console.

59 Navigation works in the app but not in a community.Medium

Some page reference types behave differently or are unsupported in Experience Cloud, and community URLs are structured differently.

Use community-appropriate page references and test in the actual site — this is a frequent surprise.

60 You need to open a sub-tab in a console app.Medium

The Workspace API (lightning/platformWorkspaceApi) — open tabs, set labels, focus and close sub-tabs.

Guard for the non-console case so the component still works on a standard record page.

61 Closing a sub-tab after save does not work.Medium

You need the Workspace API and the correct tab Id, and the call must happen after the save completes.

Also handle the case where the component is not in a console, where the API is unavailable and should degrade gracefully.

62 How do you show a toast?Easy

ShowToastEvent from lightning/platformShowToastEvent — and note it does not work in all contexts, notably some community runtimes.

Provide an inline fallback message so feedback is never lost in a context where toasts are unavailable.

63 You need to pass state through navigation.Medium

Page reference state parameters, read via CurrentPageReference on the destination.

Keep it to identifiers — URL state is visible to the user and should never carry anything sensitive or authoritative.

64 Deciding between events, LMS and LDS.Medium

Within a component tree → events and properties. Across the page or across technologies → LMS with scoping. Shared record state → LDS, which needs no messaging.

Choose the narrowest mechanism that works; broad broadcasting is harder to debug a year later.

65 An event-driven design has become hard to follow.Medium

Too many broadcast events with implicit contracts. Document each event's name, payload and publisher/subscriber, and prefer explicit parent-child wiring where the relationship is structural.

Events are for decoupling; using them where a property would do adds indirection without benefit.

66 How do you test event firing?Medium

In Jest, attach a listener to the component, trigger the interaction, and assert the event name and payload.

That makes the event an explicitly tested contract rather than an assumption.

Errors & security (67–84)

67 Error objects differ depending on their source.Medium

LDS page-level errors arrive as body arrays; Apex DML errors as body.output.fieldErrors and body.output.errors; AuraHandledException as body.message.

Write one reduceErrors utility and use it everywhere — hand-rolling the parsing per component guarantees inconsistent messages.

68 A user sees "An internal server error occurred".Easy

An unhandled Apex exception. Throw AuraHandledException with a sensible message and log the detail server-side with a correlation id.

The user should learn what to do; the developer should get the stack trace.

69 How should a component render an error?Easy

Inline, in context, with a retry affordance where retrying makes sense — not only as a toast that disappears.

And never leave the component blank: an empty panel is indistinguishable from a loading state that never finished.

70 Field-level validation errors are not shown next to the fields.Medium

Read body.output.fieldErrors and map each message to its input, or use setCustomValidity/reportValidity on base inputs.

A single aggregated message at the top of a 20-field form is a poor experience.

71 Does hiding a button protect the operation?Easy

No — the Apex method remains callable by anyone who can load the component.

Enforce CRUD, FLS and sharing server side. Client-side checks are user experience, not authorisation.

72 An @AuraEnabled method takes a SOQL filter string.Hard

That is a client-controlled query — a data-exfiltration surface regardless of intent.

Accept typed parameters, allow-list field and object names, bound the rows, and add WITH USER_MODE. Never accept a filter.

73 You render record data as HTML.Hard

Use lightning-formatted-rich-text, which sanitises. Setting innerHTML from record or user content is the classic LWC XSS.

Any field a user can type into is untrusted input, including a Case description.

74 An external script will not load.Medium

CSP. Add a Trusted Site entry, or better, bundle the library as a static resource.

Inventing a workaround to bypass CSP is a security finding, not a fix.

75 A component on a public page worries you.Hard

Every @AuraEnabled method it calls is reachable by anonymous visitors. Audit each one for CRUD/FLS enforcement, parameter validation and row bounds.

Also check nothing in the path runs without sharing or as a system-context flow. See guest hardening.

76 How do you avoid leaking fields in a DTO?Medium

Return purpose-built DTOs with only the fields the UI needs, rather than sObjects — JSON.serialize on an sObject includes everything populated.

It also decouples your component from schema changes.

77 You need to store user preferences client-side.Medium

localStorage is acceptable for per-viewer conveniences (a chosen tab, a collapsed section) — wrapped in try/catch, because it can throw or return nothing in private browsing.

Anything that must persist reliably or be read by anyone else belongs in a record.

78 Lightning Web Security changed behaviour for a library.Medium

LWS replaced Locker with a different sandboxing model, and many libraries that previously failed now work — and a few behave differently.

Re-test rather than relying on what was true under Locker, and check the migration notes.

79 You need to call an external API directly from the browser.Hard

Generally don't: CORS, CSP and credential exposure all argue against it.

Proxy through Apex with a Named Credential, which also gives you logging, retry and a single place to rotate the secret.

80 How do you handle a timeout on an imperative call?Medium

Treat it as an unknown outcome, not a failure — the server may have succeeded. Do not blindly retry a write.

Use an idempotency key so a retry is safe, or query to confirm before re-submitting.

81 Logging errors from the client.Medium

Send them to an Apex method that writes a durable log (or publishes a platform event) with the component name, the error and a correlation id.

Browser console errors are invisible to you; a logged client error is the only way to learn about failures users never report.

82 A component silently does nothing on error.Easy

Someone swallowed the rejection. Every promise needs a catch that sets a visible error state.

Silent failure is the worst outcome: the user thinks the action worked, and nobody ever investigates.

83 How do you test the error path in Jest?Medium

Emit an error through the registered test wire adapter, or reject the mocked imperative call, then assert the error UI renders.

The error case is where components most often break and where tests are most often missing.

84 What belongs in a security review of a component?Hard

Every @AuraEnabled method it calls (CRUD/FLS, parameter validation, row bounds, sharing mode), whether it is reachable by guests, any raw HTML rendering, any secret, and any client-side check mistaken for authorisation.

Then: "who can cause this to run, and in whose context?"

Judgement (85–100)

85 A record page has 12 custom components and is slow.Medium

Measure with EPT and component instrumentation, then reduce the number above the fold, consolidate Apex calls, and lazy-load what is in inactive tabs.

Often the fix is information architecture rather than code — fewer things on load, more on demand.

86 Should the component or the server shape the data?Medium

The server, generally — one DTO shaped for the UI means less client work, smaller payloads and no duplicated logic across components.

Client-side shaping also runs on every render if you put it in a getter.

87 An admin asks for a "simple" configurable table.Medium

Check what lightning-datatable plus a Dynamic Related List already does — frequently the requirement is already met.

A custom generic table is one of the most commonly rebuilt and most commonly regretted components in Salesforce projects.

88 You are asked to replicate a standard page in LWC.Medium

Push back and find out what the standard page cannot do. You will be re-implementing layouts, FLS, validation, related lists and accessibility, and then maintaining them.

Custom UI is justified by genuinely different interaction, not by appearance preference.

89 How do you keep components reusable?Medium

Presentational components take data in via properties and emit events out; container components own the data access.

A component that queries its own data is rarely reusable, because reuse almost always means a different data source.

90 A component needs to work on a record page and standalone.Medium

Accept the record Id as a public property with the recordId convention, so the record page injects it and a parent or page can pass it.

Then handle the case where it is absent, rather than assuming the record-page context.

91 How do you decide between a wire and a one-off fetch?Easy

Does the data need to stay fresh and refresh when inputs change? Wire. Is it a snapshot taken on user action? Imperative.

Writes are always imperative.

92 A library would save you a week.Medium

Weigh bundle size, CSP, LWS compatibility, accessibility and long-term maintenance — plus whether a base component already does it.

Static-resource a vetted library when it genuinely earns its place; avoid pulling in a framework for one widget.

93 You inherit a 1,500-line component.Hard

Add Jest tests for the current rendering states first, then split: a container for data access and presentational children, with shared logic in a module.

Refactoring untested UI is how you ship regressions nobody notices until a user complains.

94 How do you handle a slow server call gracefully?Easy

Show a spinner immediately, disable the triggering control, and keep the rest of the page usable.

If it may take many seconds, show progress or move it to async work with a notification — rather than an indefinite spinner.

95 Component works for you and fails for a user.Medium

Almost always permissions: object or field access, or Apex class access on their profile.

Log in as them and check. Then make the component render a clear message in that state instead of appearing broken.

96 How do you document a component's API?Easy

JSDoc on public properties and methods, design attributes with descriptions in the meta XML, documented events, and Jest tests demonstrating usage.

The tests are the documentation least likely to drift from reality.

97 Business logic has ended up in JavaScript.Medium

Move it to Apex: testable, reusable by flows and integrations, and the correct place for security enforcement.

Keep the component to presentation and interaction. Logic in the client cannot be reused and cannot be trusted.

98 You need to support a component for five years.Medium

Base components over custom markup, SLDS tokens over hard-coded styles, schema imports over string field names, LDS over hand-written CRUD, and tests for the three rendering states.

Each choice reduces the surface that platform changes can break.

99 What is the most common data-layer mistake in LWC?Hard

Not understanding cache invalidation — writing via Apex and expecting an LDS wire to notice, or passing .data to refreshApex.

Closely followed by assuming client-side checks are security, and by shipping components with no error or empty state.

100 One habit that most improves LWC data handling?Hard

Deciding, for every piece of data, who owns it and how it gets invalidated — before writing the component.

LDS, wire plus refreshApex, or imperative on demand are three different contracts, and most data bugs come from mixing them without noticing.
