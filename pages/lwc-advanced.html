LWC — Data & Communication

Wire service, Apex imports, Lightning Data Service, all four component-communication patterns, navigation, toasts, and the concepts most tutorials skip.

Four ways to get data

Choosing a data strategy

Wire service

@wire is a reactive, read-only data binding to a Salesforce data source. When its parameters change, it re-executes automatically and re-renders your component.

import { LightningElement, api, wire } from 'lwc';
import { getRecord, getFieldValue } from 'lightning/uiRecordApi';
import getContacts from '@salesforce/apex/ContactController.getContactsByAccount';
import NAME_FIELD from '@salesforce/schema/Account.Name';
import REVENUE_FIELD from '@salesforce/schema/Account.AnnualRevenue';

const FIELDS = [NAME_FIELD, REVENUE_FIELD];

export default class WireDemo extends LightningElement {
    @api recordId;
    searchKey = '';

    /* ---------- 1. Wire to a PROPERTY : simplest ---------- */
    @wire(getRecord, { recordId: '$recordId', fields: FIELDS })
    account;                         // → { data, error }

    get accountName() {
        return getFieldValue(this.account.data, NAME_FIELD);
    }

    /* ---------- 2. Wire to a FUNCTION : when you need logic ---------- */
    contacts = [];
    error;

    @wire(getContacts, { accountId: '$recordId', searchKey: '$searchKey' })
    wiredContacts({ data, error }) {
        if (data) {
            // Wire results are IMMUTABLE — clone before modifying
            this.contacts = data.map(c => ({ ...c, fullName: `${c.FirstName} ${c.LastName}` }));
            this.error = undefined;
        } else if (error) {
            this.error = error;
            this.contacts = [];
        }
    }

    handleSearch(event) {
        this.searchKey = event.target.value;   // reactive → the wire re-runs
    }
}
ConceptDetail
Reactive parametersPrefix with $: { recordId: '$recordId' }. Without $ the value is a literal, evaluated once
Wire to propertyGives you { data, error }. Great for passing straight to a template
Wire to functionGives you a hook to transform, filter or trigger side effects
TimingWires fire before connectedCallback completes and again whenever a reactive param changes. They may fire with undefined data first
ImmutabilityThe result is a read-only Proxy. Spread/clone before editing
CachingApex must be @AuraEnabled(cacheable=true); results are cached client-side
No DMLA cacheable method cannot perform DML. Use imperative Apex for writes
RefreshingrefreshApex(this.wiredResult) — you must keep the whole wired result to do this
 
import { refreshApex } from '@salesforce/apex';
import { notifyRecordUpdateAvailable } from 'lightning/uiRecordApi';

export default class RefreshDemo extends LightningElement {
    wiredContactsResult;             // keep the FULL result, not just data

    @wire(getContacts, { accountId: '$recordId' })
    wired(result) {
        this.wiredContactsResult = result;
        if (result.data) this.contacts = result.data;
    }

    async handleAfterSave() {
        await refreshApex(this.wiredContactsResult);        // refresh Apex wire
        notifyRecordUpdateAvailable([{ recordId: this.recordId }]);  // refresh LDS cache
    }
}
🧊
"Cannot assign to read only property" You tried to mutate wire data directly. Always clone: const rows = data.map(r => ({ ...r })); — and note a shallow spread doesn't deep-clone nested objects; use structuredClone(data) or JSON.parse(JSON.stringify(data)) when needed.

Importing Apex methods

The Apex side

public with sharing class ContactController {

    // cacheable=true → usable with @wire, but NO DML allowed
    @AuraEnabled(cacheable=true)
    public static List<Contact> getContactsByAccount(Id accountId, String searchKey) {
        String key = '%' + (searchKey == null ? '' : searchKey) + '%';
        return [
            SELECT Id, FirstName, LastName, Email, Title
            FROM Contact
            WHERE AccountId = :accountId
              AND (LastName LIKE :key OR FirstName LIKE :key)
            WITH USER_MODE
            ORDER BY LastName
            LIMIT 200
        ];
    }

    // No cacheable → imperative only, DML allowed
    @AuraEnabled
    public static Contact createContact(String firstName, String lastName, Id accountId) {
        try {
            Contact c = new Contact(FirstName = firstName, LastName = lastName, AccountId = accountId);
            insert as user c;
            return c;
        } catch (DmlException e) {
            // AuraHandledException gives the LWC a clean message instead of a stack trace
            throw new AuraHandledException(e.getDmlMessage(0));
        }
    }

    // Passing a complex object from JS: parameter names must match the JSON keys
    @AuraEnabled
    public static void saveRows(List<RowInput> rows) { /* ... */ }

    public class RowInput {
        @AuraEnabled public Id recordId    { get; set; }
        @AuraEnabled public Decimal amount { get; set; }
    }
}

The JavaScript side — imperative calls

import { LightningElement, api } from 'lwc';
import createContact from '@salesforce/apex/ContactController.createContact';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class ContactCreator extends LightningElement {
    @api recordId;
    firstName = '';
    lastName  = '';
    isLoading = false;

    // Promise style
    handleSavePromise() {
        createContact({ firstName: this.firstName, lastName: this.lastName, accountId: this.recordId })
            .then(result => {
                this.showToast('Success', `Created ${result.LastName}`, 'success');
                this.dispatchEvent(new CustomEvent('created', { detail: result.Id }));
            })
            .catch(error => {
                this.showToast('Error', this.reduceError(error), 'error');
            })
            .finally(() => { this.isLoading = false; });
    }

    // async/await style — usually cleaner
    async handleSave() {
        this.isLoading = true;
        try {
            const result = await createContact({
                firstName: this.firstName,
                lastName : this.lastName,
                accountId: this.recordId
            });
            this.showToast('Success', `Created ${result.LastName}`, 'success');
        } catch (error) {
            this.showToast('Error', this.reduceError(error), 'error');
        } finally {
            this.isLoading = false;
        }
    }

    reduceError(error) {
        return error?.body?.message            // AuraHandledException
            ?? error?.body?.pageErrors?.[0]?.message
            ?? error?.message
            ?? 'Unknown error';
    }

    showToast(title, message, variant) {
        this.dispatchEvent(new ShowToastEvent({ title, message, variant }));
    }
}

@AuraEnabled methods bypass nothing by accident — but they do bypass a lot by default They run in system context for FLS unless you enforce it. Always declare the class with sharing and use WITH USER_MODE / as user / stripInaccessible. This is the most common Salesforce security-review failure.

Lightning Data Service (LDS)

LDS is a shared, client-side record cache. Any component using it gets automatic FLS enforcement, cache sharing and UI refresh across every component on the page when a record changes — with no Apex at all.

Why LDS beats Apex for simple record work

import NAME_FIELD from '@salesforce/schema/Account.Name';
import INDUSTRY_FIELD from '@salesforce/schema/Account.Industry';

export default class LdsApi extends LightningElement {
    @api recordId;

    /* ---------- READ ---------- */
    @wire(getRecord, { recordId: '$recordId', fields: [NAME_FIELD, INDUSTRY_FIELD] })
    account;
    get name() { return getFieldValue(this.account.data, NAME_FIELD); }

    /* ---------- SCHEMA / PICKLISTS ---------- */
    @wire(getObjectInfo, { objectApiName: ACCOUNT_OBJECT })
    objectInfo;

    @wire(getPicklistValues, {
        recordTypeId: '$objectInfo.data.defaultRecordTypeId',
        fieldApiName: INDUSTRY_FIELD
    })
    industryOptions;

    /* ---------- RELATED LIST ---------- */
    @wire(getRelatedListRecords, {
        parentRecordId: '$recordId',
        relatedListId : 'Contacts',
        fields        : ['Contact.Name', 'Contact.Email'],
        pageSize      : 10
    })
    contacts;

    /* ---------- CREATE ---------- */
    async handleCreate() {
        const fields = {};
        fields[NAME_FIELD.fieldApiName] = 'New Account';
        const record = await createRecord({ apiName: ACCOUNT_OBJECT.objectApiName, fields });
        console.log('Created', record.id);
    }

    /* ---------- UPDATE ---------- */
    async handleUpdate() {
        await updateRecord({ fields: { Id: this.recordId, [NAME_FIELD.fieldApiName]: 'Renamed' } });
    }

    /* ---------- DELETE ---------- */
    async handleDelete() {
        await deleteRecord(this.recordId);
    }
}

Events & component communication

Pick the right communication pattern

Parent → Child

<template>
    <!-- kebab-case in markup, camelCase in JS -->
    <c-child-cmp
        record-id={selectedId}
        title="Contact details"
        items={itemList}>
    </c-child-cmp>

    <lightning-button label="Refresh child" onclick={callChildMethod}></lightning-button>
</template>
export default class Parent extends LightningElement {
    selectedId;
    itemList = [];

    // Calling a PUBLIC METHOD on the child
    callChildMethod() {
        const child = this.template.querySelector('c-child-cmp');
        child.refresh();                 // @api refresh() on the child
        // or with a ref:  this.refs.childCmp.refresh();
    }
}
import { LightningElement, api } from 'lwc';

export default class ChildCmp extends LightningElement {
    @api recordId;
    @api title;
    @api items = [];

    @api
    refresh() {
        this.loadData();
    }
}

Child → Parent

export default class ChildCmp extends LightningElement {

    handleSelect(event) {
        const contactId = event.currentTarget.dataset.id;

        // 1. Simple notification
        this.dispatchEvent(new CustomEvent('select'));

        // 2. With a payload — the detail must be primitive or a plain object
        this.dispatchEvent(new CustomEvent('contactselect', {
            detail: { contactId, source: 'list' }
        }));

        // 3. Bubbling across multiple levels
        this.dispatchEvent(new CustomEvent('deepevent', {
            detail: { contactId },
            bubbles: true,       // travel up the DOM tree
            composed: true       // cross shadow boundaries
        }));
    }
}
<template>
    <!-- on + lowercase event name. NO camelCase, NO hyphens in the event name -->
    <c-child-cmp oncontactselect={handleContactSelect}></c-child-cmp>
</template>
handleContactSelect(event) {
    const { contactId, source } = event.detail;
    this.selectedId = contactId;
}
bubblescomposedTravelsUse for
falsefalseOnly the immediate parent (default)99% of cases — keeps components decoupled
truefalseUp the DOM, stops at the shadow boundaryWithin one component's own tree
truetrueAll the way to the documentRare — deeply nested notification. Leaks implementation details
🔤
Event naming rules Must be all lowercase, no hyphens, no underscores, and must not clash with a standard DOM event name. contactselect ✅ · contactSelect ❌ · contact-select ❌. Also: never pass an object you'll later mutate — send a copy, because the receiver gets the same reference.

Publish-Subscribe (pubsub)

Before LMS existed, unrelated components on the same page communicated through a shared singleton JS module. It's legacy — you'll meet it in older codebases, and interviewers still ask about it.

// pubsub.js — a shared LWC service module
const events = {};

export const register = (eventName, callback) => {
    if (!events[eventName]) events[eventName] = [];
    events[eventName].push(callback);
};

export const unregister = (eventName, callback) => {
    if (events[eventName]) {
        events[eventName] = events[eventName].filter(cb => cb !== callback);
    }
};

export const fire = (eventName, payload) => {
    (events[eventName] || []).forEach(cb => cb(payload));
};
import { fire } from 'c/pubsub';
handleClick() { fire('accountSelected', { accountId: this.accountId }); }
import { register, unregister } from 'c/pubsub';

connectedCallback() {
    this.handler = (payload) => { this.accountId = payload.accountId; };
    register('accountSelected', this.handler);
}
disconnectedCallback() {
    unregister('accountSelected', this.handler);   // ALWAYS clean up
}

Lightning Message Service (LMS)

The supported way for any components anywhere on the page to talk — across technologies and DOM hierarchies.

import { LightningElement, wire } from 'lwc';
import { publish, MessageContext } from 'lightning/messageService';
import ACCOUNT_CHANNEL from '@salesforce/messageChannel/AccountChannel__c';

export default class AccountListLms extends LightningElement {
    @wire(MessageContext) messageContext;

    handleSelect(event) {
        publish(this.messageContext, ACCOUNT_CHANNEL, {
            accountId  : event.currentTarget.dataset.id,
            accountName: event.currentTarget.dataset.name
        });
    }
}
import { LightningElement, wire } from 'lwc';
import { subscribe, unsubscribe, MessageContext, APPLICATION_SCOPE }
       from 'lightning/messageService';
import ACCOUNT_CHANNEL from '@salesforce/messageChannel/AccountChannel__c';

export default class AccountDetailLms extends LightningElement {
    subscription = null;
    accountId;

    @wire(MessageContext) messageContext;

    connectedCallback() {
        if (this.subscription) return;
        this.subscription = subscribe(
            this.messageContext,
            ACCOUNT_CHANNEL,
            (message) => this.handleMessage(message),
            { scope: APPLICATION_SCOPE }      // receive even from other tabs/regions
        );
    }

    disconnectedCallback() {
        unsubscribe(this.subscription);
        this.subscription = null;
    }

    handleMessage(message) {
        this.accountId = message.accountId;
    }
}
🎚️
Scope matters Default scope = active area (the current console tab/region only). APPLICATION_SCOPE = the whole application, including inactive console tabs and the utility bar. Choose deliberately — application scope in a console app can produce surprising cross-tab updates.

Interview questions

1 @wire versus imperative Apex — give me the decision rule.Easy

@wire is reactive and automatic: it runs on load and again whenever a $-prefixed parameter changes. It requires cacheable=true, returns read-only data and cannot do DML. Use it for displaying data that follows a record or a filter.

Imperative runs only when you call it, allows DML, returns mutable data and gives you full control of loading and error state. Use it for saves, deletes and button clicks. Short version: reads that follow a record → wire; writes and user-initiated actions → imperative.

2 Why does modifying wired data throw "Cannot assign to read only property"?Medium

Wire results are immutable Proxies — the framework caches and may share them across components, so mutation is blocked. Clone before changing: const rows = data.map(r => ({ ...r }));.

Note a spread is a shallow copy — nested objects are still frozen. For deep structures use structuredClone(data) or JSON.parse(JSON.stringify(data)). Same reason console.log of wire data looks unhelpful until you clone it.

3 After an imperative save, the wired list is stale. Fix it properly.Medium

Store the entire wired result, not just data, then call refreshApex(this.wiredResult). For records managed by LDS, also call notifyRecordUpdateAvailable([{ recordId }]) so every other component on the page refreshes too.

Why the naive approach fails: the wire cache is only invalidated automatically when a reactive parameter changes. Re-assigning a local array doesn't touch the cache, so a page refresh brings the stale data straight back.

4 Describe all four communication patterns and when each applies.Medium
  • Parent → Child: @api property, or an @api method the parent calls via querySelector/refs.
  • Child → Parent: dispatchEvent(new CustomEvent('name', { detail })), parent listens with onname={handler}.
  • Siblings: bubble to the common parent which passes back down — or LMS if there's no shared ancestor you control.
  • Anywhere on the page, across LWC / Aura / Visualforce: Lightning Message Service.

Pub-sub is the legacy predecessor to LMS: LWC-only, no schema, and unreliable across page regions.

5 What are the event naming rules, and what do bubbles and composed do?Hard

Event names must be all lowercase, with no hyphens or underscores, and must not clash with a standard DOM event. contactselect ✅, contactSelect ❌, contact-select ❌ — because the on + name handler syntax is case-insensitive in HTML.

bubbles: false, composed: false (the default) reaches only the immediate parent — correct for ~99% of cases and keeps components decoupled. bubbles: true travels up the DOM but stops at the shadow boundary. composed: true escapes the shadow boundary entirely and reaches the document — powerful but it leaks your internals and makes the component hard to reason about.

6 Why prefer Lightning Data Service over Apex?Medium

A shared client-side cache: three components asking for the same record produce one server request, and when any of them updates it, all of them refresh automatically. You also get FLS and sharing enforcement for free, and no Apex class or test to maintain.

Drop to Apex when LDS can't do it: multi-record queries with complex filters, aggregates, unsupported objects, or multi-record transactional DML.

7 How do you secure an @AuraEnabled method?Hard

They run in system context for FLS by default — nothing is enforced for you, which is why this is the most common security-review failure in LWC projects. Do all of:

  • Declare the class with sharing.
  • Enforce FLS/CRUD: WITH USER_MODE on queries, insert as user or AccessLevel.USER_MODE on DML, or Security.stripInaccessible() before returning.
  • Bind all SOQL variables; validate every input — the client can call the method with any arguments.
  • Throw AuraHandledException so the UI gets a clean message rather than a stack trace.
8 How do you get real-time updates into an LWC when another user changes data?Hard

Subscribe to a Platform Event or Change Data Capture channel with lightning/empApi: subscribe('/event/Order_Shipped__e', -1, callback) in connectedCallback, and unsubscribe in disconnectedCallback.

Never poll with setInterval — it burns API calls, scales badly with user count, and still isn't real-time. Use replay id -1 for new events only, -2 to replay the retained window after a reconnect.

9 LMS scope — what's the difference and why does it matter?Medium

The default is active area: the subscriber only receives messages published in the same console tab or page region. APPLICATION_SCOPE receives messages from anywhere in the application, including inactive console tabs and the utility bar.

It matters in Service Console: with application scope, selecting an account in one tab can update a component in a different tab, which is either exactly what you wanted or a confusing bug. Choose deliberately.

Quick check

1. Two components in different regions of a record page must share a selection. Best approach?
Events only travel up their own DOM tree — components in separate page regions have no common ancestor you control. LMS is designed for exactly this.
2. Your @wire Apex method needs to insert a record. What happens?
Cacheable methods must be side-effect free so the framework can cache and replay them. Any write must be an imperative call.
3. After saving via Apex, your @wire list doesn't refresh. Fix?
The wire cache is only invalidated when a reactive parameter changes or you explicitly refresh it. For LDS-managed records, also call notifyRecordUpdateAvailable().
