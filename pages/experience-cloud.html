Experience Cloud

Portals, help centres and partner sites built on your Salesforce data — and the guest-user security model that has caused more data breaches than any other Salesforce feature.

What it is

Experience Cloud (formerly Communities) publishes a branded website backed by your Salesforce org. External people log in — or browse anonymously — and interact with real records, subject to a sharing model designed for people who are not employees.

Customer portal / Help Centre

Case submission and status, Knowledge search, self-service. The classic case-deflection play.

Partner portal

Deal registration, lead distribution, co-selling. Partners see Leads and Opportunities you share with them.

Public site

Unauthenticated marketing pages, event registration, public knowledge — served to the guest user.

Employee intranet

Internal collaboration for users who don't need full CRM access.

Microsites & forms

Lightweight campaign pages that write straight into Salesforce.

Commerce storefronts

B2B/B2C Commerce sites built on the same platform foundation.

The three-role limit Each partner/customer account can have up to 3 portal roles (Executive, Manager, User) by default, forming a mini hierarchy per account. High-volume Customer Community users have no role at all — which is exactly why Sharing Sets exist.

Sharing for external users

How an external user gets record access

Sharing Sets — the one to understand

// Conceptually, a Sharing Set says:
//   grant this community user access to records where
//   Case.ContactId  ==  User.ContactId
//   Case.AccountId  ==  User.Contact.AccountId
//
// Access level: Read Only or Read/Write, per object.
// Works for: Account, Contact, Case, Opportunity, Work Order, custom objects
//            with a lookup path back to the user's Contact or Account.

Sharing Sets exist because high-volume Customer Community users have no role, so the role hierarchy and ordinary owner-based sharing rules simply don't apply to them. A Share Group then lets internal users see records owned by those high-volume external users.

Guest user security — read this twice

🚨
This is the single biggest breach source in Salesforce A misconfigured guest user profile has repeatedly exposed entire customer databases publicly. Salesforce responded with a series of mandatory Guest User Security release updates. Treat the guest user as a hostile anonymous visitor, because that's exactly what it is.

// A guest-facing Apex controller done properly
public with sharing class PublicCaseController {

    @AuraEnabled
    public static Id submitCase(String subject, String description, String email) {
        // 1. Validate — the caller is anonymous and untrusted
        if (String.isBlank(subject) || subject.length() > 255) {
            throw new AuraHandledException('Invalid subject');
        }
        if (!Pattern.matches('^[^@\\s]+@[^@\\s]+\\.[^@\\s]+$', email)) {
            throw new AuraHandledException('Invalid email');
        }
        // 2. Never accept a record Id from the client and act on it blindly
        // 3. Create only what is needed, with an explicit owner
        Case c = new Case(
            Subject     = subject.escapeHtml4(),
            Description = description,
            SuppliedEmail = email,
            Origin      = 'Web',
            OwnerId     = DEFAULT_QUEUE_ID
        );
        insert c;                       // consider AccessLevel.SYSTEM_MODE deliberately, and document why
        return c.Id;                    // return the Id only if the page needs it
    }
}

Guest security checklist

  • Audit the guest profile — object and field permissions, tabs, Apex class access, Visualforce page access.
  • Set external OWD to Private on every object the site touches.
  • Review Guest User Sharing Rules — each one is a deliberate public exposure.
  • Check every @AuraEnabled method reachable by the guest profile; assume an attacker calls it directly, not through your page.
  • Turn on Clickjack protection and CSP in the site's security settings.
  • Rate-limit and CAPTCHA any form that creates records.
  • Test as the guest user — browse the site logged out, and try the API with no session.

Interview questions

1 Why do Sharing Sets exist?Medium

Because high-volume Customer Community users have no role. Without a role there's no role hierarchy and owner-based sharing rules can't reach them, so the normal model has nothing to work with.

A Sharing Set grants access by lookup path instead — "share Cases where Case.ContactId equals the user's Contact". A Share Group then lets internal users see records owned by those external users.

2 What's the maximum access a guest user can have to a record?Easy

Read Only — the platform enforces this, and guest users cannot own records. Access can only come from Guest User Sharing Rules, which are a separate, restricted category; ordinary sharing rules don't apply to guests. The "Secure guest user record access" setting enforcing this is mandatory and must stay enabled.

3 Your public site exposes data it shouldn't. Where do you look?Hard
  1. External OWD — is it Private for the exposed object?
  2. Guest User Sharing Rules — each one is a deliberate public grant; is there a stale one?
  3. Guest profile — object permissions, FLS, and especially any View All.
  4. Apex — a guest-accessible @AuraEnabled method in a class without with sharing runs in system context and will happily return everything. Attackers call these directly, not through your page.
  5. Site-level settings — public API access, clickjack protection, CSP.
4 Customer Community vs Customer Community Plus vs Partner Community.Medium

Customer Community: high-volume B2C, no roles, no reports, Cases and Knowledge — sharing via Sharing Sets. Customer Community Plus: adds roles, reports and dashboards, and participates in normal sharing rules. Partner Community: adds Leads, Opportunities and Campaigns for channel sales, with roles, delegated administration and Super User access. Pick the cheapest licence that supports the objects and sharing model the use case genuinely needs.

5 LWR or an Aura template — how do you decide?Medium

LWR for public, high-traffic, brand-led sites where page speed and design control matter — it's pre-rendered and CDN-served, and substantially faster. Aura templates (Customer Service/Napili) when you want the rich out-of-the-box service components — case lists, Knowledge, feeds — working within days rather than building them. Note LWR supports LWC only, so any existing Aura components would need rewriting.

6 How do you deflect cases on a help centre, and prove it worked?Medium

Surface Knowledge search prominently, show suggested articles while the user types their case subject, and add an Einstein bot for routine questions. Publish articles to the public channel with the right data categories.

Prove it with Experience Cloud's case deflection tracking (article viewed, then no case created), article view counts and ratings, and by trending case volume per channel against site traffic. The business value is straightforward: a deflected case costs nothing; an agent-handled one costs an agent-hour.

7 A partner must see opportunities owned by colleagues at their company. How?Hard

Partner Community licences do have roles — each partner account gets up to 3 portal roles forming a mini hierarchy. Place the manager at a higher portal role than their colleagues and the hierarchy grants access upward, exactly as internally.

For broader access within the account, enable Partner Super User access, which lets a user see records owned by others at their account and below in the portal role hierarchy. Avoid solving this with a broad sharing rule — that would leak data across partner accounts.

8 What happens in Apex when the running user is a guest?Hard

Nothing special is enforced for you — which is the danger. A class without a sharing declaration runs without sharing when it's the entry point, and @AuraEnabled methods don't enforce FLS by default. So a guest-callable method can return records the site was never meant to show.

Always declare with sharing, use WITH USER_MODE or stripInaccessible, validate every parameter (never trust a record Id from the client), and assume the method is being called directly with crafted arguments rather than through your page.

Quick check

1. High-volume Customer Community users can't see their own Cases. Why?
No role means no hierarchy and no owner-based sharing rules. Sharing Sets grant access through a lookup path instead.
2. What's the maximum record access a guest user can be granted?
Platform-enforced since the guest user security release updates. Guests also cannot own records.
3. Which template would you choose for a fast, heavily branded public marketing site?
LWR trades ready-made components for speed and design freedom, which is the right trade for public brand-led sites.
