APIs & Callouts

The complete integration toolkit: what an API is, inbound vs outbound, authentication, REST and SOAP callouts, every standard API, composite requests, status codes, Apex REST/SOAP, Outbound Messages and External Services — each with a use case.

What is an API?

An Application Programming Interface is a contract that lets two systems exchange data without knowing anything about each other's internals. It defines what you can ask for, how to ask, and what comes back.

The restaurant analogy — and the real mapping

Authentication & OAuth 2.0

Every inbound call needs an access token. You get one by completing an OAuth flow against a Connected App.

Setting up a Connected App

  • Setup → App Manager → New Connected App (or "New External Client App" in newer orgs).
  • Enable OAuth Settings, set the Callback URL (e.g. https://oauth.pstmn.io/v1/callback for Postman).
  • Select scopes: api (access data), refresh_token offline_access (long-lived), openid, full.
  • Save and wait ~10 minutes for it to propagate — a classic source of confusing 400 errors.
  • Copy the Consumer Key (client_id) and Consumer Secret (client_secret).
  • Manage → Edit Policies: set "Permitted Users" (usually Admin approved users are pre-authorised) and IP relaxation.
  • Assign a profile or permission set to the Connected App so your integration user can use it.

Named Credentials & Remote Site Settings

Before Salesforce can call out to any URL, that endpoint must be whitelisted.

Remote Site Setting (old way)

Just whitelists the URL. You manage tokens, headers and refresh logic yourself — usually storing secrets in a custom setting, which is a security smell.

req.setEndpoint('https://api.erp.com/v1/orders');
req.setHeader('Authorization', 'Bearer ' + token);
vs

Named Credential (right way)

Stores the URL and the authentication. Salesforce injects the auth header and refreshes tokens for you. Secrets never appear in code.

req.setEndpoint('callout:ERP_API/v1/orders');
// no Authorization header needed at all
  • Setup → Named Credentials → External Credential — choose the authentication protocol (OAuth 2.0, Basic, JWT, AWS Signature, Custom).
  • Add a Principal (Named Principal for one shared identity, or Per-User Principal for individual auth).
  • Grant access — add the External Credential to a permission set.
  • Create the Named Credential pointing at the base URL and the External Credential.
  • Use it in Apex as callout:My_Named_Credential/path.
// Named Credential with merge fields for custom headers
HttpRequest req = new HttpRequest();
req.setEndpoint('callout:ERP_API/v1/orders');
req.setMethod('GET');
// Salesforce injects: Authorization: Bearer <managed token>
HttpResponse res = new Http().send(req);

// Calling YOUR OWN org's API (self-callout) — still needs a Named Credential
req.setEndpoint('callout:Self_Org/services/data/v62.0/sobjects/Account/001xx');

REST callouts (outbound)

The callout sequence — and the DML trap
public with sharing class ErpCalloutService {

    /* ---------------- GET ---------------- */
    public static Order__c fetchOrder(String orderNumber) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:ERP_API/v1/orders/' + EncodingUtil.urlEncode(orderNumber, 'UTF-8'));
        req.setMethod('GET');
        req.setHeader('Accept', 'application/json');
        req.setTimeout(30000);                       // ms, max 120000

        HttpResponse res = new Http().send(req);

        if (res.getStatusCode() != 200) {
            throw new CalloutException('ERP GET failed: ' + res.getStatusCode()
                                       + ' — ' + res.getBody());
        }
        Map<String, Object> body = (Map<String, Object>) JSON.deserializeUntyped(res.getBody());
        return new Order__c(
            External_Id__c = (String)  body.get('id'),
            Amount__c      = (Decimal) body.get('total'),
            Status__c      = (String)  body.get('status'));
    }

    /* ---------------- POST ---------------- */
    public static String createOrder(Order__c o) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:ERP_API/v1/orders');
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setBody(JSON.serialize(new Map<String, Object>{
            'customerRef' => o.Account__c,
            'total'       => o.Amount__c,
            'lines'       => buildLines(o)
        }));

        HttpResponse res = new Http().send(req);
        if (res.getStatusCode() == 201) {
            Map<String, Object> body = (Map<String, Object>) JSON.deserializeUntyped(res.getBody());
            return (String) body.get('id');
        }
        throw new CalloutException('Create failed: ' + res.getStatus() + ' ' + res.getBody());
    }

    /* ---------------- PATCH / PUT / DELETE ---------------- */
    public static void updateOrder(String id, Map<String, Object> changes) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:ERP_API/v1/orders/' + id);
        req.setMethod('PATCH');
        req.setHeader('Content-Type', 'application/json');
        req.setBody(JSON.serialize(changes));
        new Http().send(req);
    }

    public static void deleteOrder(String id) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:ERP_API/v1/orders/' + id);
        req.setMethod('DELETE');
        new Http().send(req);
    }

    /* ---------------- Other request features ---------------- */
    public static void extras() {
        HttpRequest req = new HttpRequest();
        req.setEndpoint('callout:ERP_API/v1/files');
        req.setMethod('POST');
        req.setBodyAsBlob(someBlob);                            // binary upload
        req.setCompressed(true);                                // gzip the body
        req.setClientCertificateName('MyOrgCert');              // mutual TLS
        req.setHeader('Authorization',
            'Basic ' + EncodingUtil.base64Encode(Blob.valueOf('user:pass')));  // if no Named Cred
    }
}

Resilient callouts — retry with backoff

public class ResilientCallout implements Queueable, Database.AllowsCallouts {
    private Integer attempt;
    private static final Integer MAX_ATTEMPTS = 3;
    private static final Set<Integer> RETRYABLE = new Set<Integer>{408, 429, 500, 502, 503, 504};

    public ResilientCallout(Integer attempt) { this.attempt = attempt; }

    public void execute(QueueableContext ctx) {
        HttpResponse res;
        try {
            res = new Http().send(buildRequest());
        } catch (CalloutException e) {          // timeout / DNS / TLS
            retryOrFail(null, e.getMessage());
            return;
        }
        if (RETRYABLE.contains(res.getStatusCode())) {
            retryOrFail(res.getStatusCode(), res.getBody());
        } else if (res.getStatusCode() >= 200 && res.getStatusCode() < 300) {
            handleSuccess(res);
        } else {
            logPermanentFailure(res);           // 4xx — retrying won't help
        }
    }

    private void retryOrFail(Integer code, String message) {
        if (attempt < MAX_ATTEMPTS && !Test.isRunningTest()) {
            // Delay grows with each attempt (API 61+ supports a delay in minutes)
            System.enqueueJob(new ResilientCallout(attempt + 1), attempt * 5);
        } else {
            insert new Integration_Error__c(Status_Code__c = code, Message__c = message);
        }
    }
}
🎯
Use case When an Opportunity is Closed Won, Salesforce must create the order in SAP. The trigger enqueues a Queueable that POSTs to SAP, stores the returned SAP order number on the Opportunity, and retries up to three times on 5xx before logging an error and alerting the integration team.

SOAP callouts (outbound)

For SOAP services you generate a strongly-typed Apex stub from the service's WSDL.

  • Get the WSDL file from the provider.
  • Setup → Apex Classes → Generate from WSDL, upload the file.
  • Salesforce generates an Apex class per WSDL namespace, containing request/response types and a *Port class with one method per operation.
  • Add a Remote Site Setting or Named Credential for the endpoint.
  • Call it like normal Apex.
// Generated stub usage
public class WeatherClient {
    public static Decimal getTemperature(String city) {
        // The generated port class
        weatherService.WeatherSoap svc = new weatherService.WeatherSoap();
        svc.endpoint_x = 'callout:Weather_API';       // override with a Named Credential
        svc.timeout_x  = 30000;
        svc.inputHttpHeaders_x = new Map<String, String>{ 'X-Api-Version' => '2' };

        try {
            weatherService.WeatherResponse resp = svc.GetWeather(city, 'metric');
            return resp.temperature;
        } catch (CalloutException e) {
            throw new IntegrationException('Weather service failed: ' + e.getMessage(), e);
        }
    }
}

Hand-rolling SOAP over HTTP

When WSDL2Apex fails (it chokes on complex schemas, xsd:choice, imports and RPC-encoded WSDLs) you can build the envelope by hand:

String envelope =
    '<?xml version="1.0" encoding="UTF-8"?>' +
    '<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"' +
    '                  xmlns:web="http://example.com/weather">' +
    '  <soapenv:Header/>' +
    '  <soapenv:Body>' +
    '    <web:GetWeather><web:City>' + city.escapeXml() + '</web:City></web:GetWeather>' +
    '  </soapenv:Body>' +
    '</soapenv:Envelope>';

HttpRequest req = new HttpRequest();
req.setEndpoint('callout:Weather_API');
req.setMethod('POST');
req.setHeader('Content-Type', 'text/xml; charset=UTF-8');
req.setHeader('SOAPAction', '"http://example.com/weather/GetWeather"');
req.setBody(envelope);

HttpResponse res = new Http().send(req);

// Parse with Dom.Document
Dom.Document doc = res.getBodyDocument();
Dom.XmlNode body = doc.getRootElement()
    .getChildElement('Body', 'http://schemas.xmlsoap.org/soap/envelope/');
String temp = body.getChildElement('GetWeatherResponse', 'http://example.com/weather')
                  .getChildElement('Temperature', 'http://example.com/weather')
                  .getText();
🧱
WSDL2Apex limits Max 1 MB WSDL, no RPC-encoded WSDLs, no xsd:choice/xsd:any, no WSDL imports, and the generated class must stay under the Apex class size limit. For anything gnarly, hand-roll the XML or put a middleware layer in front.

Standard REST API (inbound)

Salesforce exposes every object and record through a REST API — no code required on your side.

BASE = https://MyDomain.my.salesforce.com/services/data/v62.0

# Discover versions and resources
GET  /services/data/
GET  $BASE/

# ---- CRUD ----
POST   $BASE/sobjects/Account/                  {"Name":"Acme"}          → 201 + id
GET    $BASE/sobjects/Account/001xx000003DGb2   → 200 + all fields
GET    $BASE/sobjects/Account/001xx?fields=Name,Industry

PATCH  $BASE/sobjects/Account/Legacy_Id__c/A-1001   {"Name":"Acme"}
#        → 201 if created, 204 if updated. No need to know the Salesforce Id.

# ---- Query ----
GET $BASE/query?q=SELECT+Id,Name+FROM+Account+WHERE+Industry='Technology'+LIMIT+10
GET $BASE/query/01g5j00000ABCDEabc-2000        # next page via nextRecordsUrl
GET $BASE/queryAll?q=...                       # includes deleted/archived

# ---- Search ----
GET $BASE/search?q=FIND+{Acme}+RETURNING+Account(Id,Name)
GET $BASE/parameterizedSearch?q=Acme&sobject=Account

# ---- Metadata & describe ----
GET $BASE/sobjects/                            # list all objects
GET $BASE/sobjects/Account/describe            # fields, picklists, record types
GET $BASE/sobjects/Account/listviews

# ---- Other useful resources ----
GET  $BASE/limits                              # remaining API calls, storage
GET  $BASE/sobjects/Account/001xx/Contacts     # related records
POST $BASE/actions/custom/flow/My_Flow         # invoke a flow
GET  $BASE/ui-api/record-ui/001xx              # UI API: layout + data + FLS
🔑
Why upsert-by-External-Id is the most important REST call The external system never has to store or look up Salesforce Ids. It just says "here is customer A-1001" and Salesforce creates or updates it. This makes integrations idempotent — safe to replay after a failure.

Composite REST API

Bundle multiple operations into one HTTP round trip — critical for mobile apps, high-latency networks, and staying inside API call allocations.

Four composite flavours
// POST /services/data/v62.0/composite
{
  "allOrNone": true,
  "compositeRequest": [
    {
      "method": "POST",
      "url": "/services/data/v62.0/sobjects/Account",
      "referenceId": "refAccount",
      "body": { "Name": "Acme India", "Industry": "Technology" }
    },

      "method": "POST",

      "referenceId": "refContact",

      "url": "/services/data/v62.0/sobjects/Opportunity",

🎯
Use case A mobile app registers a new customer: it must create an Account, a Contact and an Opportunity, then read back the Account. Four separate REST calls = four round trips over a mobile network and four API calls against your allocation, with no atomicity. One composite call = one round trip, one API call, and all-or-none rollback.

Apex REST API (custom inbound endpoints)

When the standard API isn't the right shape — you need business logic, a custom payload, or a single call that does several things — expose your own REST endpoint.

@RestResource(urlMapping='/orders/*')
global with sharing class OrderRestService {

    /* ---------------- GET /services/apexrest/orders/{orderNumber} ---------------- */
    @HttpGet
    global static void getOrder() {
        RestRequest  req = RestContext.request;
        RestResponse res = RestContext.response;
        res.addHeader('Content-Type', 'application/json');

        // Path parameter: everything after the last /
        String orderNumber = req.requestURI.substring(req.requestURI.lastIndexOf('/') + 1);
        // Query parameter: ?includeLines=true
        Boolean includeLines = req.params.get('includeLines') == 'true';

        try {
            List<Order> orders = [
                SELECT Id, OrderNumber, Status, TotalAmount, Account.Name
                FROM Order WHERE OrderNumber = :orderNumber WITH USER_MODE LIMIT 1
            ];
            if (orders.isEmpty()) {
                res.statusCode = 404;
                res.responseBody = Blob.valueOf(JSON.serialize(
                    new Map<String, Object>{ 'error' => 'Order not found', 'orderNumber' => orderNumber }));
                return;
            }
            res.statusCode = 200;
            res.responseBody = Blob.valueOf(JSON.serialize(new OrderDto(orders[0], includeLines)));

        } catch (Exception e) {
            res.statusCode = 500;
            res.responseBody = Blob.valueOf(JSON.serialize(
                new Map<String, Object>{ 'error' => e.getMessage() }));
        }
    }

    /* ---------------- POST — parameters are auto-deserialised from the JSON body ---------------- */
    @HttpPost
    global static OrderResult createOrder(String accountExternalId,
                                          List<LineItemDto> lines,
                                          String poNumber) {
        // Body: { "accountExternalId":"A-1001", "poNumber":"PO-77",
        //         "lines":[{"sku":"X1","qty":2}] }
        Savepoint sp = Database.setSavepoint();
        try {
            Account acc = [SELECT Id FROM Account WHERE Legacy_Id__c = :accountExternalId LIMIT 1];
            Order o = new Order(AccountId = acc.Id, PoNumber = poNumber,
                                Status = 'Draft', EffectiveDate = Date.today());
            insert o;
            insertLines(o.Id, lines);
            RestContext.response.statusCode = 201;
            return new OrderResult(true, o.Id, null);

        } catch (QueryException e) {
            RestContext.response.statusCode = 404;
            return new OrderResult(false, null, 'Account not found: ' + accountExternalId);
        } catch (Exception e) {
            Database.rollback(sp);
            RestContext.response.statusCode = 400;
            return new OrderResult(false, null, e.getMessage());
        }
    }

    /* ---------------- PATCH / PUT / DELETE ---------------- */
    @HttpPatch
    global static OrderResult updateStatus(String status) { /* ... */ return null; }

    @HttpPut
    global static OrderResult replaceOrder(OrderDto order) { /* ... */ return null; }

    @HttpDelete
    global static void deleteOrder() {
        String id = RestContext.request.requestURI.substring(
                        RestContext.request.requestURI.lastIndexOf('/') + 1);
        delete [SELECT Id FROM Order WHERE OrderNumber = :id];
        RestContext.response.statusCode = 204;
    }

    /* ---------------- DTOs ---------------- */
    global class OrderResult {

Apex SOAP API (custom inbound SOAP)

The SOAP equivalent: mark methods with the webservice keyword and Salesforce generates a WSDL for you.

global with sharing class OrderSoapService {

    // Inner class for the response — members need the webservice keyword too
    global class OrderResponse {
        webservice Boolean success;
        webservice String  orderNumber;
        webservice String  message;
    }

    // The 'webservice' keyword makes this a SOAP operation
    webservice static OrderResponse createOrder(String accountExtId, Decimal amount) {
        OrderResponse resp = new OrderResponse();
        try {
            Account acc = [SELECT Id FROM Account WHERE Legacy_Id__c = :accountExtId LIMIT 1];
            Order o = new Order(AccountId = acc.Id, Status = 'Draft',
                                EffectiveDate = Date.today());
            insert o;
            resp.success     = true;
            resp.orderNumber = [SELECT OrderNumber FROM Order WHERE Id = :o.Id].OrderNumber;
        } catch (Exception e) {
            resp.success = false;
            resp.message = e.getMessage();
        }
        return resp;
    }

    webservice static List<Order> getOrdersByAccount(Id accountId) {
        return [SELECT Id, OrderNumber, Status FROM Order
                WHERE AccountId = :accountId WITH USER_MODE];
    }
}
  • Write the class with webservice static methods.
  • Setup → Apex Classes → your class → Generate WSDL.
  • Send the WSDL to the consuming system; endpoint is /services/Soap/class/OrderSoapService.
  • They call login() against the Enterprise/Partner WSDL first to get a session id.
webservice keyword rules
Method must be static and the class global
Cannot be used in a trigger, or in a class that implements Batchable/Schedulable
Cannot be private; overloading is not supported
Member variables of returned inner classes must also be marked webservice
Supported types: primitives, sObjects, lists of them, and inner classes with webservice members
⚖️
Apex REST vs Apex SOAP Choose Apex REST for anything new: lighter, JSON, easier to test in Postman, better tooling. Choose Apex SOAP only when the consuming system demands a WSDL contract — common with older enterprise middleware and some ESBs.

Outbound Messages

A declarative, no-code way to send a SOAP message to an external endpoint when a record changes. Configured in Workflow Rules or Approval Processes — no Apex at all.

Outbound Message with guaranteed retry
  • Setup → Workflow Actions → Outbound Messages → New.
  • Choose the object and the endpoint URL (must be HTTPS with a valid certificate).
  • Select fields to send, and optionally include the Session Id so the receiver can call back into Salesforce.
  • Pick the user to send as — this determines the session's permissions.
  • Attach it to a Workflow Rule (legacy), an Approval Process action, or call it from a Flow via an outbound-message-triggering field update.
  • Click "Click for WSDL" and give that WSDL to the receiving developer so they can build the listener.
<!-- What Salesforce sends -->
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/">
  <soapenv:Body>
    <notifications xmlns="http://soap.sforce.com/2005/09/outbound">
      <OrganizationId>00D5j000000XXXX</OrganizationId>
      <ActionId>04k5j000000YYYY</ActionId>
      <SessionId>00D5j...!AQ</SessionId>
      <EnterpriseUrl>https://.../services/Soap/c/62.0/00D5j</EnterpriseUrl>
      <PartnerUrl>https://.../services/Soap/u/62.0/00D5j</PartnerUrl>
      <Notification>
        <Id>04l5j000000ZZZZ</Id>
        <sObject xsi:type="sf:Opportunity">
          <sf:Id>0065j00000ABCDE</sf:Id>
          <sf:Amount>150000.0</sf:Amount>
          <sf:StageName>Closed Won</sf:StageName>
        </sObject>
      </Notification>
    </notifications>
  </soapenv:Body>
</soapenv:Envelope>

<!-- What the endpoint MUST return, or Salesforce keeps retrying -->
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/">
  <soapenv:Body>
    <notificationsResponse xmlns="http://soap.sforce.com/2005/09/outbound">
      <Ack>true</Ack>
    </notificationsResponse>
  </soapenv:Body>
</soapenv:Envelope>

✅ Strengths

  • No code — pure configuration
  • Guaranteed delivery with automatic retry for 24 h
  • Asynchronous — never slows the user's save
  • Doesn't consume Apex callout limits
  • Can include a Session Id for callbacks
  • Up to 100 notifications batched per message

❌ Limitations

  • SOAP/XML only — no REST, no JSON
  • One-way — the Ack carries no data back into Salesforce
  • Only fields from one object (plus limited related fields)
  • No transformation or conditional payload logic
  • Tied to Workflow/Approval — and Workflow Rules are retired for new creation
  • Endpoint must be publicly reachable HTTPS
🔄
Modern alternative For new work, prefer Platform Events (pub/sub, JSON, many subscribers) or a record-triggered Flow with an asynchronous path calling an HTTP action. Outbound Messages remain valuable when you specifically need guaranteed retry with zero code.

External Services

Point Salesforce at an OpenAPI (Swagger) specification and it generates invocable actions automatically — so admins can call an external REST API from Flow with no Apex.

From OpenAPI spec to a Flow action
  • Create a Named Credential for the API's base URL and auth.
  • Setup → External Services → Add an External Service, choose "From API Specification".
  • Paste or upload the OpenAPI schema (JSON; OpenAPI 2.0 or 3.0).
  • Select the operations you want to expose.
  • Salesforce generates Apex classes and one invocable action per operation.
  • Drop them into a Flow as an Action, or call the generated Apex directly.
{
  "swagger": "2.0",
  "info": { "title": "Credit Check API", "version": "1.0.0" },
  "host": "api.creditbureau.com",
  "basePath": "/v1",
  "schemes": ["https"],
  "paths": {
    "/score": {
      "post": {
        "operationId": "getCreditScore",
        "consumes": ["application/json"],
        "parameters": [{
          "in": "body", "name": "body", "required": true,
          "schema": { "type": "object",
            "properties": { "taxId": {"type":"string"}, "companyName": {"type":"string"} } }
        }],
        "responses": {
          "200": { "description": "Score returned",
            "schema": { "type": "object",
              "properties": { "score": {"type":"integer"}, "rating": {"type":"string"} } } }
        }
      }
    }
  }
}

ExternalService.CreditCheckAPI service = new ExternalService.CreditCheckAPI();

    new ExternalService.CreditCheckAPI.getCreditScore_Request();
req.body = new ExternalService.CreditCheckAPI_ScoreRequest();

✅ Good for

  • Admins calling REST APIs from Flow with no code
  • Well-documented partner APIs with a clean spec
  • Rapid prototyping of an integration
  • Keeping request/response types in sync with the provider

❌ Watch out

  • The OpenAPI schema must be well-formed and is quite strict (max ~100 KB, limited features)
  • No support for some auth patterns or complex nested schemas
  • Limited error handling — a fault path in Flow is all you get
  • Callouts still can't run on a Flow's immediate path after DML — use an async path
🎯
Use case A credit bureau offers a REST endpoint with an OpenAPI spec. Register it as an External Service, then an admin builds a Screen Flow: the sales rep clicks "Run Credit Check" on the Account, the flow calls the action and writes the score back — zero Apex, zero developer time.

Interview questions

1 Explain inbound vs outbound and what changes in your design.Easy

Inbound — Salesforce is the server. You configure a Connected App, an OAuth flow, a least-privilege integration user, and you watch the daily API request allocation. Tools: standard REST/SOAP API, Apex REST/SOAP, Composite, Bulk.

Outbound — Salesforce is the client. You configure a Named Credential, live within 100 callouts and 120 seconds per transaction, and you must deal with the DML-before-callout restriction. Tools: Apex HTTP callouts, WSDL2Apex, Outbound Messages, External Services.

2 Which OAuth flow would you use for a nightly server-to-server job, and why not the others?Hard

JWT Bearer. It signs an assertion with a private key whose certificate is on the Connected App — no password stored anywhere, no browser prompt, unaffected by MFA policies or password expiry, and the key can live in a secrets vault.

Client Credentials is the simpler alternative when you can nominate a run-as user on the Connected App. Web Server needs a human to consent, so it can't run unattended. Username-Password is deprecated, blocked by default in new orgs, transmits credentials on every call and can't satisfy MFA — never use it in production.

3 Why is upsert by External Id the most important call in integration?Medium

Because it makes the call idempotent. The external system issues PATCH /sobjects/Account/Legacy_Id__c/A-1001 without ever knowing or storing a Salesforce Id — Salesforce creates the record (201) or updates it (204).

That matters because networks fail: if a timeout leaves you unsure whether the call succeeded, you can safely replay it. Without idempotency, every retry risks a duplicate order. Note a 300 response means the External Id matched multiple records — a data problem to fix, not a retry.

4 Walk me through the status codes you'd handle in a callout, and which are retryable.Medium

Families: 2xx success, 3xx redirect, 4xx your fault, 5xx their fault.

Retryable: 408, 429 (with backoff — honour Retry-After), 500, 502, 503, 504. Not retryable: 400 (malformed), 403 (permissions or API limit), 404 (wrong URL/version), 405, 415 — these need a code or config fix. 401 is the special case: retry once after refreshing the token. And remember 204 with an empty body is success for PATCH and DELETE, not an error.

5 A trigger updates a record then calls an API and fails. Why, and what's the fix?Medium

"You have uncommitted work pending". Salesforce won't hold an open database transaction while waiting on an external system, so a callout can't follow DML in the same transaction.

Fix: move the callout to a Queueable implements Database.AllowsCallouts (preferred — it takes sObjects, returns a job Id, supports chaining and Finalizers) or @future(callout=true). In Flow, use the asynchronous path. Both run after commit.

6 Named Credential vs Remote Site Setting.Easy

A Remote Site Setting only whitelists a URL — you still build the Authorization header, store the secret somewhere (usually a custom setting, which is a security smell) and handle token refresh yourself.

A Named Credential stores the endpoint and the authentication. Salesforce injects the auth header and refreshes OAuth tokens automatically, and no secret ever appears in code: req.setEndpoint('callout:ERP_API/v1/orders'). Modern orgs split this into an External Credential (the auth protocol and principal) plus the Named Credential (the URL), with access granted through a permission set.

7 When would you write Apex REST instead of using the standard REST API?Medium

When the operation is business logic, not CRUD. "Submit an order" might validate the customer, create the Order, create line items, apply pricing and return an order number — one call, one transaction, one clean contract for the partner.

Also when you want to hide your internal data model, aggregate several objects into one payload, or version the endpoint (/v1/orders) independently of your schema. Stick to the standard API for plain record CRUD — it needs no code, no tests and no maintenance.

8 What does the Composite API solve, and what are its four variants?Hard

It collapses multiple operations into one HTTP round trip and one API call — critical on mobile networks and for staying inside your daily allocation.

  • /composite — up to 25 chained subrequests that reference each other via @{refId.id}, optionally all-or-none.
  • /composite/batch — 25 independent subrequests, no referencing, each succeeding or failing alone.
  • /composite/tree — up to 200 records in a nested parent/child tree of one object.
  • /composite/graph — up to 500 records across 75 graphs, each graph committing independently.
9 When is an Outbound Message still the right tool in 2026?Medium

When you need guaranteed delivery with automatic retry for 24 hours and absolutely no code, and the receiver can accept SOAP and return <Ack>true</Ack>. Nothing else in the platform gives you that retry behaviour declaratively.

Its limits are why it's rarely chosen for new work: SOAP/XML only, one-way (the Ack carries no data back), a single object's fields, no transformation logic, and it's tied to Workflow Rules or Approval actions — and Workflow Rules can no longer be created. Platform Events are the modern answer.

10 What are External Services and where do they fall short?Medium

You register an OpenAPI (Swagger) specification and Salesforce generates Apex types plus invocable actions, so an admin can call an external REST API from Flow with no code. Requires a Named Credential for the base URL and auth.

Shortfalls: the schema must be well-formed and fairly simple (size limits, no deeply nested or polymorphic types), error handling is limited to a Flow fault path, some auth patterns aren't supported, and the callout still can't run on a flow's immediate path after DML. For anything complex, hand-written Apex gives you retry logic and proper error capture.

Quick check

1. A trigger updates a record then makes a callout, and fails. Why, and what's the fix?
Salesforce won't hold a database transaction open while waiting on an external system. Async runs after commit, which resolves it.
2. An external system must create a Salesforce Account without ever knowing Salesforce Ids. Best approach?
Upsert by External Id is idempotent: replaying the same call is safe, which is exactly what you want in an integration.
3. You get a 401 from a Salesforce REST call that worked an hour ago. Cause?
401 = unauthenticated (INVALID_SESSION_ID). 403 would be the permissions answer; 404 the missing-record answer.
4. Which needs zero code and retries automatically for 24 hours?
Guaranteed retry with no code is the Outbound Message's unique selling point — the trade-off is SOAP-only, one-way, single-object.
