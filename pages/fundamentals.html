Salesforce Fundamentals

What Salesforce actually is under the hood — multitenancy, metadata, the runtime engine, org types and the vocabulary every other module assumes you already know.

What is Salesforce?

Salesforce is a cloud-based CRM platform. Two halves matter:

  • CRM applications — ready-made apps for sales, service, marketing and commerce (Sales Cloud, Service Cloud…).
  • The platform (Lightning Platform) — the toolkit underneath that lets you extend those apps or build entirely new ones with clicks (declarative) or code (programmatic).

CRM stands for Customer Relationship Management: a single system that stores every customer interaction — leads, deals, support cases, emails — so the whole company works from one record of truth instead of scattered spreadsheets.

💡
Interview one-liner "Salesforce is a multitenant, metadata-driven SaaS + PaaS platform. Customers share infrastructure but their customisations live as metadata, which keeps every org isolated and upgradeable three times a year."

Cloud service models — where Salesforce sits

On-Premise vs IaaS vs PaaS vs SaaS
Salesforce sells SaaS apps and the PaaS underneath them. You always own your data; Salesforce owns everything below the app.

Multitenancy

Thousands of customers ("tenants") run on the same application instance, database and hardware. Think of an apartment building: shared foundation, plumbing and lifts, but each flat is locked and privately furnished.

One codebase, many isolated orgs
Your data and customisations are separated by Org ID at the data layer, not by separate servers.
✅

Benefits

  • No hardware to buy or patch
  • 3 free upgrades a year, no downtime
  • Economies of scale = lower cost
  • Instant scalability
⚖️

The trade-off

  • Governor limits — one tenant can't hog resources
  • No OS/DB access
  • Upgrades happen on Salesforce's schedule
🔒

Isolation

  • Every row carries an Org ID
  • Queries are rewritten to filter by it
  • You can never see another tenant's data
🚦
Why governor limits exist — remember this answer Because the platform is multitenant, a runaway loop in your org would slow down everyone else's. Limits are the platform's way of enforcing fair resource sharing. See Governor Limits.

Metadata-driven architecture

This is the single most important architectural idea in Salesforce. When you create a custom object Invoice__c with five fields, Salesforce does not run CREATE TABLE. It writes rows into internal metadata tables. Your data then lands in a giant shared table where each field maps to a generic value0…valueN column, and indexes are "pivoted" separately.

How your custom object is really stored
Consequence: schema changes are instant and safe, but you can't tune the database — you tune your queries instead.

What counts as metadata?

Metadata (configuration)

Objects, fields, page layouts, Apex classes, flows, profiles, validation rules, record types, reports.

Deployable between orgs.

Data (records)

Accounts, Contacts, Opportunities, Cases — the actual business rows.

Not deployed with metadata; needs Data Loader or seeding.

The blurry middle

Custom Metadata Types are records that behave like metadata — deployable and queryable. See Custom Settings vs Metadata.

Licenses — three kinds people confuse

👤

User License

The base license, one per user. Determines the maximum a user could ever access. E.g. Salesforce, Salesforce Platform, Customer Community.

🎟️

Permission Set License

Adds capability on top of the user license without changing it. E.g. CRM Analytics, Sales Console User.

🔧

Feature License

Turns on one specific feature for a user. E.g. Marketing User, Knowledge User, Service Cloud User.

🔗
Key rule A permission set can never grant more than the user license allows. If a Platform-licensed user can't see Opportunities, no permission set will fix it — the license itself excludes standard CRM objects.

The release cycle

Salesforce ships three releases a year — Spring (Feb), Summer (Jun), Winter (Oct) — named for the season ahead of the calendar year, e.g. Winter '26 ships in October 2025.

  • Release notes published ~5 weeks before, and sandboxes on preview instances upgrade first.
  • Preview window — test your customisations on a sandbox running the new version.
  • Production upgrade — happens in a 5-minute rolling window with no downtime.
  • Critical Updates / Release Updates — behaviour changes you must activate before an enforcement deadline. Check Setup → Release Updates every release.
📌
Practical habit status.salesforce.com tells you your instance (e.g. NA152), maintenance windows and the exact release date. The API version of your classes stays where you left it — old code keeps its old behaviour after upgrade.

Record IDs — the 15 vs 18 character question

Every record has an ID. The first 3 characters are the object key prefix, which is a fast way to identify an object from a URL.

PrefixObjectPrefixObject
001Account500Case
003Contact00QLead
006Opportunity005User
00DOrganizationa0XCustom objects
  • 15-character — case-sensitive, shown in the UI/URL.
  • 18-character — case-insensitive, adds a 3-char checksum. Used by the API, and required by tools like Excel that lose case.
  • In Apex the two are interchangeable: Id comparisons normalise to 18. Convert with String.valueOf(id) (always 18) or the formula CASESAFEID().

Interview questions

1 Explain multitenancy and how Salesforce keeps one customer's data away from another's.Easy

Thousands of customers share the same application instance, database and hardware. Isolation is achieved at the data layer, not by separate servers: every row carries an Org ID, and the query optimizer rewrites every query to filter on it. Your customisations live as metadata rows tagged with the same Org ID. The trade-off for this efficiency is governor limits — enforced fairness so one tenant can't starve the others.

2 What does "metadata-driven architecture" actually mean?Medium

When you create Invoice__c, Salesforce doesn't run CREATE TABLE. It writes rows into internal metadata tables describing the object and its fields; your records land in a shared data table where values map to generic columns, with indexes pivoted separately.

Consequences: schema changes are instant and safe, configuration is deployable as metadata, and the same platform serves every tenant. But you get no database tuning — you optimise queries and rely on selective filters and custom indexes instead.

3 Which sandbox would you use for performance testing, and why not the others?Easy

Full sandbox — it's the only type that copies all production data, so load and performance results are meaningful. Developer (200 MB) and Developer Pro (1 GB) copy metadata only; Partial Copy takes a template-defined sample, which is fine for UAT but useless for performance. Note the refresh intervals: Developer daily, Partial 5 days, Full 29 days — that alone often drives the environment strategy.

4 15 vs 18 character record IDs — why do both exist?Medium

The 15-character ID is case-sensitive and appears in the UI and URLs. The 18-character ID appends a 3-character checksum making it case-insensitive, which matters for tools that lose case — Excel, some databases, older ETL. The API returns 18. In Apex the Id type normalises them so comparisons work either way; in formulas use CASESAFEID().

5 A release is coming. What do you do to prepare?Medium

Read the release notes (~5 weeks ahead), then test on a sandbox that sits on a preview instance so it upgrades first. Critically, check Setup → Release Updates for behaviour changes with enforcement deadlines and activate them in a sandbox before they become mandatory. Production upgrades happen in a ~5-minute rolling window with no downtime. Existing Apex keeps its saved API version, so old code retains its old behaviour after the upgrade.

6 A user has a Salesforce Platform licence and can't see Opportunities. Can a permission set fix it?Hard

No. A permission set can never grant more than the user licence permits, and the Platform licence excludes standard CRM objects such as Opportunity, Lead, Case and Campaign. The fix is a licence change, not a permission change. This is the distinction between a user licence (the ceiling), a permission set licence (adds capability on top) and a feature licence (turns on one feature such as Marketing User).

7 Where does MVC map on the Salesforce platform?Easy

Model — objects, fields, relationships, validation rules, record types. View — Lightning App Builder, LWC, Aura, Visualforce, page layouts, Dynamic Forms. Controller — Apex classes and triggers, Flow, standard controllers, approval processes. Asking "which layer is this feature?" is a fast way to pick the right tool for a requirement.

8 Why is there no SELECT * in SOQL?Medium

Because of multitenancy and the shared data table. Returning every field of every row would be unbounded work on infrastructure shared with other tenants, and would blow heap limits. You must name the fields you need, which keeps queries selective and predictable. When you genuinely need all fields, build the list dynamically from Schema.describe or a Field Set — and accept the heap cost consciously.

Quick check

1. Why does Salesforce enforce governor limits?
Multitenancy is the reason. Shared infrastructure requires enforced fairness — every limit traces back to this.
2. You need a sandbox with real production data for performance testing. Which one?
Only a Full sandbox copies all data. Partial Copy takes a template-defined sample; Developer copies metadata only.
3. A record ID starts with 006. What object is it?
001 = Account, 003 = Contact, 006 = Opportunity, 500 = Case, 00Q = Lead.
